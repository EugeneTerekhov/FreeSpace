# ADR 0001: GUI на Tauri 2 + React 18 вместо egui

- **Статус**: Accepted
- **Дата**: 2026-11-16
- **Контекст**: FreeSpace 002 — единый нативный интерфейс нового поколения
- **Связанные документы**: [spec.md](../../specs/002-native-ui-redesign/spec.md),
  [plan.md](../../specs/002-native-ui-redesign/plan.md),
  [research.md](../../specs/002-native-ui-redesign/research.md),
  [ui-redesign-plan.md](../ui-redesign-plan.md)

## Контекст

FreeSpace — утилита Windows для анализа и освобождения дискового пространства. Ядро, CLI,
операции и WinAPI реализованы на Rust. Существующий GUI на egui/eframe содержит 24 экрана и
полностью покрывает функциональность, но не даёт нужного визуального языка, CSS-тем,
DOM-доступности и инструментов визуальной регрессии. Старый интерфейс нигде не выпускался,
поэтому нет необходимости поддерживать его параллельно.

Конституция (принцип «Технологические и платформенные ограничения») допускает Tauri только
при обоснованной необходимости веб-технологий и требует, чтобы нативная функциональность не
снижалась. Настоящий ADR фиксирует это обоснование.

## Решение

Перевести весь GUI на **Tauri 2 + React 18 + TypeScript + Vite**:

- `apps/freespace-desktop` — единственный GUI-крейт, бинарь `freespace-gui.exe`.
- React отвечает только за представление и ввод; Rust остаётся единственным владельцем
  доменной логики, WinAPI, сканирования, операций, журнала, карантина и настроек.
- `crates/freespace-app` — тонкий прикладной слой (DTO, пагинация, агрегация Treemap,
  миграция UI-настроек), чтобы не дублировать логику egui-views.
- `apps/freespace-gui` и egui-зависимости удаляются в рамках 002. Второй UI, beta-флаг,
  side-by-side и отдельная cutover-фаза не создаются.
- Все 24 экрана, тёмная/светлая/системная темы, DPI 100–200%, RU/EN, доступность и
  офлайн-поставка входят в 002.

## Обоснование

1. **Точный перенос языка интерфейса.** Макет `web/` задаёт палитру, типографику, плотность,
   поверхности, радиусы, Treemap и функциональный motion. React/CSS позволяют перенести его
   1:1, не изобретая эквиваленты в immediate-mode GUI.
2. **Две темы и системная тема.** CSS custom properties и `prefers-color-scheme` дают
   мгновенное переключение без перезапуска и без двух разных дизайнов.
3. **Доступность.** DOM-семантика, ARIA, focus trap, `aria-live` и Narrator поддерживаются
   WebView2/UIA напрямую; в egui эквивалентный уровень требует значительно большего объёма
   работы.
4. **Тесты.** Playwright, Vitest/RTL, axe и визуальная регрессия — зрелые инструменты для
   24 экранов; Tauri E2E проверяет реальный IPC и упаковку.
5. **Нативная функциональность не снижается.** Все WinAPI-вызовы остаются в
   `freespace-platform`; Tauri-команды не вызывают WinAPI и не получают доступ к ФС в обход
   `freespace-ops`. NTFS, MFT/USN, длинные пути, права, elevation, журнал и карантин
   сохраняются.
6. **Производительность.** 10 млн узлов обслуживаются пейджингом, виртуализацией,
   агрегированными тайлами Treemap и throttle событий; полный JSON дерева запрещён.
   Бюджеты 200 мс / 30 fps / 4 ГБ проверяются отдельно.

## Рассмотренные альтернативы

| Альтернатива | Почему отклонена |
|--------------|------------------|
| Остаться на egui/eframe | Нет нужного визуального контроля, CSS-тем, DOM-доступности и Playwright; перенос макета потребовал бы дублировать дизайн-систему. |
| Slint | Меньше экосистема и хуже перенос React-макета; доступность и визуальная регрессия слабее. |
| WinUI 3 | Тяжёлая интеграция Rust + C++/C#; усложняет сборку и паритет с CLI. |
| Web-приложение в браузере | Нарушает нативность окна, офлайн-поставку и доступ к системным возможностям. |
| React 19 | Не соответствует утверждённому макету и добавляет миграционный риск без выгоды для 002. |

## Последствия

### Положительные

- Единый визуальный язык на 24 экранах; токены вместо хардкода.
- Обе темы, системная тема, DPI и reduced motion — штатными средствами CSS.
- Доступность и визуальная регрессия проверяются автоматически.
- Один GUI-крейт вместо двух; egui удаляется, поддержка не удваивается.
- React-компоненты переиспользуются между экранами, тестами и галереей.

### Отрицательные и риски

- Появляется WebView2 runtime и зависимость от его версии; нужен offline fixed runtime.
- Node.js/Vite/TypeScript добавляют вторую цепочку сборки и CI-задачи.
- IPC-контракт и порционная передача данных требуют дисциплины и тестов.
- Память WebView2 входит в бюджет 4 ГБ; нужны замеры всего дерева процессов.
- Размер установщика растёт из-за WebView2; решение фиксируется в research/spike.
- Потеря пользовательских настроек при миграции недопустима; нужна резервная копия и тесты.

### Меры снижения

- WebView2 fixed runtime в поставке; `offlineInstaller` — резерв при превышении бюджета.
- CSP `default-src 'self'`, минимальные capabilities, без fs/shell/http-плагинов.
- Профиль WebView2 в `data/webview2`; настройки в `data/settings.toml`; без localStorage.
- Пагинация, виртуализация, Canvas Treemap, throttle 10–20 Гц.
- CI: Rust + frontend + Tauri E2E + visual + a11y + network guard.
- Полная замена egui: один UI, без beta-флага и side-by-side.

| Принцип | Соответствие | Обоснование |

| II. Точный учёт места | PASS | Все размеры считает Rust; UI показывает результат и тип метрики. |
| III. Производительность | PASS | Ядро не меняется; пейджинг, виртуализация, Canvas, бюджеты и бенчмарки. |

| V. Тест-первый подход | PASS | Rust-тесты + Vitest/RTL/Playwright/tauri-driver/axe/visual; фикстуры только временные/VHD. |
| VI. Паритет CLI/GUI | PASS | Одно ядро; CLI-контракт защищён golden-тестами; матрица паритета. |
| VII. Офлайн/приватность | PASS | Нет remote/телеметрии; CSP; fixed WebView2; данные в `data`. |
| Tech constraints: Tauri с обоснованием | PASS | Настоящий ADR фиксирует необходимость веб-технологий и отсутствие потерь нативной функциональности. |

## Безопасность

- CSP: `default-src 'self'; connect-src ipc: http://ipc.localhost; img-src 'self' data:;
  style-src 'self' 'unsafe-inline'; script-src 'self'`.
- Capabilities: `core:default` + точечные window/event + single-instance; без fs/shell/http.
- `withGlobalTauri: false`; devtools выключены в release.
- Все пути канонизируются; выход за выбранную область запрещён.
- Команды не принимают shell/URL/SQL; сетевые вызовы запрещены.
- Логи локальные, без содержимого файлов и секретов.

## WebView2 и офлайн

- Fixed runtime входит в установщик и portable-сборку; версия фиксируется при релизе.
- Если размер установщика превышает бюджет — установщик переходит на `offlineInstaller`,
  portable сохраняет fixed runtime.
- Профиль WebView2 принудительно размещается в `data/webview2`.
- Фоновые сетевые компоненты Edge отключаются аргументами; network guard в E2E подтверждает
  отсутствие запросов.

## Миграция и замена

- Старый egui-интерфейс нигде не выпущен; 002 полностью заменяет его.
- `apps/freespace-gui` и egui-зависимости удаляются; исходники остаются в истории git.
- Имя `freespace-gui.exe` сохраняется; ярлыки, скрипты и контекстное меню не ломаются.
- Существующие настройки, журнал, карантин и снимки читаются новым клиентом; перед миграцией
  создаётся резервная копия.
- CLI, коды возврата, форматы отчётов и снимков не меняются.
- Установщик: Tauri NSIS; Inno выводится после переноса сценариев удаления `data` и меню.

## Открытые вопросы, закрываемые spike

- Точный API Tauri 2 для `data_directory` WebView2 в выбранной версии (fallback —
  `WEBVIEW2_USER_DATA_FOLDER`).
- Размер fixed runtime vs `offlineInstaller` и бюджет установщика.
- Стабильность `tauri-driver`/Edge WebDriver на Windows CI.
- Точные значения светлой палитры по итогам контраст-тестов.
