# Research: FreeSpace — технические решения

**Feature**: `001-freespace-disk-analyzer` | **Date**: 2026-11-15

Все ключевые технические неизвестные из плана разрешены ниже в формате «решение — обоснование —
альтернативы».

## 1. UI-фреймворк

- **Decision**: `egui`/`eframe` с `egui_extras` для таблиц и собственной отрисовкой Treemap.
- **Rationale**: нативный immediate-mode UI без WebView, полный контроль над отрисовкой
  прямоугольников и виртуализацией, простая интеграция с фоновыми потоками через каналы,
  минимальные накладные расходы, один бинарник.
- **Alternatives considered**: Tauri (WebView, HTML/JS-фронтенд — сложнее обеспечить
  производительность Treemap на миллионах узлов, дополнительные задержки и размер дистрибутива);
  Slint (меньше экосистема для кастомной отрисовки); WinUI 3 (тяжёлая интеграция с Rust, C++/C#).

## 2. Быстрое сканирование NTFS

- **Decision**: открытие тома через `CreateFileW("\\.\X:")` и перечисление записей MFT через
  `FSCTL_ENUM_USN_DATA` (`USN_RECORD_V2`), с дедупликацией по File Reference Number (FRN).
  Если бенчмарки не достигают цели 8 ТБ / 60 с — включается оптимизированный парсер сырых
  записей MFT за флагом функции.
- **Rationale**: документированный и стабильный интерфейс, даёт имя, родителя, FRN, атрибуты,
  размеры и метки времени за один проход; дедупликация по FRN корректно учитывает жёсткие ссылки.
- **Alternatives considered**: собственный парсер `$MFT` (максимальная скорость, но высокая
  сложность и риск несовместимости); `FindFirstFileExW` (медленно на миллионах файлов);
  сторонние крейты (`ntfs`, `usn-journal`) — используются как справочная реализация, но
  критичный путь пишется на `windows` crate.

## 3. Fallback-сканирование не-NTFS и работа без прав

- **Decision**: параллельный обход дерева на `jwalk` + `rayon` с ограничением параллелизма и
  обработкой ошибок доступа; метод сканирования сохраняется в сессии и показывается в UI/отчёте.
- **Rationale**: `jwalk` эффективно использует несколько ядер и корректно обрабатывает длинные
  пути; предсказуемое поведение без административных прав.
- **Alternatives considered**: `walkdir` (проще, но медленнее); собственный обходчик (больше кода
  и тестов).

## 4. Инкрементальное обновление через USN

- **Decision**: сохранение `USN_JOURNAL_DATA_V2` (JournalID, NextUSN) в сессии; при повторном
  сканировании — `FSCTL_READ_USN_JOURNAL` и применение записей к дереву. При смене JournalID или
  переполнении журнала — полное пересканирование с уведомлением.
- **Rationale**: единственный надёжный механизм дельта-изменений NTFS; резко ускоряет повторный
  анализ и мониторинг.
- **Alternatives considered**: повторный полный обход (медленно); `ReadDirectoryChangesW`
  (работает только в реальном времени, не для повторного анализа).

## 5. Модель хранения дерева

- **Decision**: структуры-массивы (SoA) в арене: `NodeId = u32`, индексы parent/child/sibling,
  имена в общем UTF-8-арене со смещениями, `SizeMetrics` (логический/на диске/физический),
  FRN, атрибуты, метки времени. Оценка: ~80–100 байт на узел, до 4 ГБ на 10 млн узлов.
- **Rationale**: отсутствие per-node аллокаций, кэш-дружественность, быстрый обход и сортировка;
  укладывается в бюджет памяти.
- **Alternatives considered**: `Rc<RefCell<Node>>` (фрагментация и накладные расходы); плоские
  path-строки (дорого по памяти); внешняя БД (медленные запросы при интерактивной навигации).

## 6. Treemap

- **Decision**: алгоритм squarified treemap (Bruls et al.), собственная отрисовка в egui,
  уровни детализации: узлы меньше порога пикселей агрегируются; кэш раскладки на уровень зума.
- **Rationale**: оптимальная читаемость прямоугольников, предсказуемая производительность,
  отсутствие внешних зависимостей.
- **Alternatives considered**: slice-and-dice (плохие пропорции); cushion treemap (сложнее);
  готовые WebGL-библиотеки (несовместимы с egui).

## 7. Поиск дубликатов

- **Decision**: конвейер «размер → частичный хеш (первые и последние 64 КиБ) → полный хеш
  SHA-256/MD5 → побайтовое сравнение». Кеш хешей в SQLite: таблица `hash_cache` по ключу
  `(VolumeSerial, FRN, Size, MTime)` и таблица `analysis_hash_cache` по ключу `(Path, Size,
  MTime)` для файлов без FRN; параллелизм `rayon`; крупные файлы читаются потоково.
- **Rationale**: исключает ложные совпадения, минимизирует чтение диска, ускоряет повторные
  проверки.
- **Alternatives considered**: сравнение только по имени/размеру (ложные совпадения); только
  полный хеш (медленно); BLAKE3 (быстрее, но пользователи ожидают MD5/SHA-256).

## 8. Шредер

- **Decision**: перезапись с `FILE_FLAG_WRITE_THROUGH`, паттерны «нули» и «случайные данные»
  (криптостойкий ГПСЧ), настраиваемое число проходов; после перезаписи — переименование в
  случайное имя, усечение и удаление; на SSD — `FSCTL_FILE_LEVEL_TRIM` и предупреждение о
  выравнивании износа с явным подтверждением.
- **Rationale**: соответствует требованиям спецификации и честно отражает ограничения SSD;
  не требует драйвера.
- **Alternatives considered**: один проход нулями (быстрее, слабее); крипто-erase (неприменимо к
  произвольным файлам); внешние утилиты (нарушают автономность).

## 9. Определение блокировок и разблокировка

- **Decision**: Restart Manager API (`RmStartSession`/`RmRegisterResources`/`RmGetList`) для
  списка процессов; «мягкое» снятие — `RmShutdown` (грациозное закрытие), «жёсткое» — завершение
  процесса после подтверждения. Для драйверных блокировок — `MoveFileExW` с
  `MOVEFILE_DELAY_UNTIL_REBOOT`.
- **Rationale**: официальный механизм без kernel-драйвера; закрытие чужих дескрипторов из
  user-mode невозможно, а завершение процесса — прозрачная и безопасная альтернатива.
- **Alternatives considered**: драйвер-разблокировщик (сложность, подпись, риски); перечисление
  дескрипторов через `NtQuerySystemInformation` (информативно, но не позволяет закрыть чужой
  дескриптор).

## 10. Длинные пути

- **Decision**: все внутренние операции — через verbatim-пути (`\\?\` и `\\?\UNC\`), собственный
  слой нормализации; проверка предела 32 000 символов до операции; полные пути в журнале.
- **Rationale**: не зависит от политики `LongPathsEnabled`; покрывает требования FR-051…FR-053.
- **Alternatives considered**: требовать включения политики (неприемлемо для пользователя);
  `dunce`-нормализация (полезна, но недостаточна для гарантий).

## 11. Права NTFS и владельцы

- **Decision**: `GetNamedSecurityInfoW`/`SetNamedSecurityInfoW`, `LookupAccountSidW`,
  включение привилегий `SeRestorePrivilege`, `SeTakeOwnershipPrivilege`, `SeSecurityPrivilege`
  через `AdjustTokenPrivileges`; предпросмотр ACE до применения.
- **Rationale**: штатные Security API; корректная работа с наследованием и аудитом.
- **Alternatives considered**: `icacls`/PowerShell (внешние процессы, медленно, небезопасно);
  прямая запись дескрипторов без привилегий (невозможна).

## 12. Ссылки, сжатие, sparse и ADS

- **Decision**: hard links — дедупликация по FRN; junction/symlink — определение по
  `FILE_ATTRIBUTE_REPARSE_POINT` и `FSCTL_GET_REPARSE_POINT`; сжатие/sparse — `GetCompressedFileSizeW`
  и `FSCTL_QUERY_ALLOCATED_RANGES` для точного размера на диске (для остальных файлов —
  округление до кластера); ADS — `FindFirstStreamW`/`FindNextStreamW` по требованию и в режиме
  глубокого анализа.
- **Rationale**: точность там, где она важна, без массовых дорогих запросов к каждому файлу.
- **Alternatives considered**: `GetCompressedFileSizeW` для всех файлов (слишком медленно);
  игнорирование ADS (занижение размеров).

## 13. Формат снимков

- **Decision**: `.fssnap` — CBOR (`ciborium`) с версией схемы, колонночная структура узлов,
  сжатие `zstd`; метаданные тома, метод сканирования, настройки; сравнение — потоковое слияние
  отсортированных путей.
- **Rationale**: компактность, скорость сериализации, версионирование и потоковое сравнение без
  загрузки всего файла в память.
- **Alternatives considered**: JSON (большой размер, медленно); SQLite-файл (сложнее обновлять
  версии схемы); protobuf (нужна кодогенерация, избыточно).

## 14. Чтение архивов

- **Decision**: ZIP — `zip`; 7z — `sevenz-rust`; TAR/GZ — `tar` + `flate2`; ISO — `iso9660`;
  RAR — опциональный `unrar` с внешней `unrar.dll` и явной пометкой в интерфейсе.
- **Rationale**: покрытие распространённых форматов без внешних процессов; RAR — из-за
  лицензионных ограничений только опционально.
- **Alternatives considered**: вызов 7-Zip CLI (зависимость от установленного ПО, медленно).

## 15. Метаданные

- **Decision**: `kamadak-exif` для EXIF; `lofty` для аудио (битрейт, длительность); `mp4parse`
  и разбор заголовков Matroska для видео (разрешение, кодек, длительность); `pelite` для
  `VS_VERSIONINFO` исполняемых файлов; все чтения — в фоне и с таймаутом.
- **Rationale**: зрелые крейты, отсутствие внешних бинарников, устойчивость к повреждённым файлам.
- **Alternatives considered**: `ffprobe` (внешняя зависимость); `exiftool` (внешний процесс).

## 16. Мониторинг записи на диск

- **Decision**: ETW-сессия реального времени `Microsoft-Windows-Kernel-File` через `ferrisetw`
  (события записи с PID и путём); при отсутствии прав — fallback на опрос
  `GetProcessIoCounters` (скорость по процессам без путей) и хвост USN-журнала (пути без PID).
- **Rationale**: ETW даёт точную атрибуцию «процесс → путь → объём»; fallback сохраняет
  работоспособность без административных прав.
- **Alternatives considered**: только USN (нет PID); драйвер minifilter (избыточно, подпись);
  WMI (`Win32_PerfFormattedData_PerfProc_Process` — без путей).

## 17. Локальное хранилище

- **Decision**: SQLite (`rusqlite`, bundled) для журнала операций, индекса карантина и кеша
  хешей; настройки — TOML; всё хранится в `<exe_dir>\data`. `%APPDATA%`, `%LOCALAPPDATA%`,
  `%ProgramData%` и временные каталоги не используются. При отсутствии прав на запись настройки
  остаются в памяти, а операция сообщает об ошибке. Миграции схемы — встроенные и версионированные.
- **Rationale**: транзакционность журнала, восстановление после сбоев, простые миграции и
  предсказуемое удаление всех следов вместе с папкой приложения; отказ от профиля исключает
  скрытые записи и упрощает портативность.
- **Alternatives considered**: `%APPDATA%`/`%LOCALAPPDATA%` (запрещены требованием полного отказа);
  `%ProgramData%` (требует прав и является системным); JSON-файлы журнала (риск повреждения);
  внешняя СУБД (избыточно).

## 18. Интеграция в контекстное меню

- **Decision**: записи реестра `HKCU\Software\Classes\*\shell`, `Directory\shell`, `Drive\shell`
  (и `HKLM` при повышении прав) через `winreg`, с `MUIVerb`, `Icon` и командой запуска. Пункты
  отключены по умолчанию и управляются настройкой `context_menu_enabled`; портативная сборка
  компилируется без функции `context-menu` и без зависимости `winreg`.
- **Rationale**: работает на Windows 10 и 11 (в Windows 11 — в расширенном меню «Показать
  дополнительные параметры»), не требует COM-сервера и установщика; отключение по умолчанию
  убирает неожиданные записи в реестре.
- **Alternatives considered**: `IExplorerCommand` COM + MSIX (нативное меню Windows 11, но
  существенно сложнее); всегда включённая интеграция (нарушает требование «по умолчанию пусто»);
  сторонние оболочки (неприемлемо).

## 19. Локализация и настройки

- **Decision**: `rust-i18n` с файлами `locales/ru.toml` и `locales/en.toml`, переключение языка
  в рантайме без перезапуска; настройки — `serde` + TOML, горячее применение где возможно.
- **Rationale**: простой формат, поддержка плюрализации, отсутствие тяжёлых зависимостей.
- **Alternatives considered**: Fluent (мощнее, но избыточно для двух языков); gettext (сложнее).

## 20. Тестирование файловых операций

- **Decision**: unit-тесты на временных каталогах (`tempfile`/`assert_fs`); интеграционные тесты
  CLI через `assert_cmd`; тесты MFT/прав/блокировок — только при `FREESPACE_ADMIN_TESTS=1` на
  отдельном тестовом NTFS-томе (VHD); бенчмарки `criterion` для сканирования, хеширования и
  Treemap.
- **Rationale**: безопасность реальных данных, воспроизводимость в CI (windows-latest даёт
  администратора), измеримость бюджета производительности.
- **Alternatives considered**: тесты на основном диске разработчика (опасно); моки WinAPI
  (не проверяют реальную семантику ФС).

## 21. Упаковка и портативная сборка

- **Decision**: портативный ZIP-дистрибутив собирается с `--no-default-features` (без компонента
  контекстного меню) и содержит каталог `data`; установщик Inno Setup не регистрирует пункты меню
  и при удалении вызывает `context-menu uninstall` для обеих областей и удаляет `{app}\data`.
  Подпись кода — отдельная задача релиза.
- **Rationale**: портативность важна для системных администраторов; отказ от AppData и
  отключённое по умолчанию меню делают поведение предсказуемым, а удаление — полным.
- **Alternatives considered**: `portable.flag` (больше не нужен, режим хранения единственный);
  установка в `%LOCALAPPDATA%\Programs` (запрещена требованием); MSIX (ограничивает реестровые
  интеграции); Chocolatey/Winget (дополнительные каналы, не заменяют ZIP).

## 22. Экспорт отчётов

- **Decision**: CSV — `csv`; XML — `quick-xml`; HTML — собственный шаблон с экранированием;
  Excel — `rust_xlsxwriter` (XLSX); потоковая запись для больших отчётов; документированные
  схемы в `contracts/`.
- **Rationale**: нативные крейты без внешних зависимостей, корректные кодировки, поддержка
  больших объёмов.
- **Alternatives considered**: генерация XLS (устаревший формат); HTML через шаблонизатор
  (избыточно).

## 23. Идентификаторы и служебные зависимости

- **Decision**: операции, сессии и элементы карантина идентифицируются `uuid` v4; идентификатор
  тома выводится детерминированно (UUID v5) из нормализованной точки монтирования. Крейт `uuid`
  (`v4`, `v5`, `serde`) добавлен в `freespace-core`, остальные модули используют реэкспорт
  `freespace_core::Uuid`.
- **Rationale**: стабильные идентификаторы нужны журналу, карантину и отмене операций; UUID v5
  сохраняет ссылки на том между запусками; реэкспорт не позволяет версиям `uuid` разойтись по
  крейтам.
- **Alternatives considered**: собственный генератор строк (нет гарантий уникальности и
  стандартного формата); серийный номер тома как идентификатор (меняется при переформатировании
  и не покрывает точки монтирования).

## 24. Организация интеграционных тестов

- **Decision**: межкрейтовые тесты и общие фикстуры файловой системы находятся в отдельном
  пакете `freespace-tests` (`tests/Cargo.toml`), поскольку корневой манифест виртуальный и
  каталог `tests/` иначе не собирается.
- **Rationale**: `tests/common/mod.rs` переиспользуется всеми сценариями, а
  `cargo test --workspace` запускает их в CI.
- **Alternatives considered**: дублировать фикстуры в каждом крейте (рассинхронизация); тесты
  на реальных дисках (запрещены конституцией).

## 25. Заставка и иконка приложения

- **Decision**: визуальная идентичность зафиксирована в готовых файлах
  `apps/freespace-desktop/src-tauri/icons/icon.png` (256×256), `icon.ico` (16–256 px) и
  `apps/freespace-desktop/ui/public/splash.png`. Tauri встраивает ICO через `tauri-build`, а
  заставка загружается из `public`.
- **Rationale**: заставка закрывает интервал загрузки настроек, а одно и то же изображение
  используется в заголовке окна, на панели задач, в проводнике и в установщике. Заранее
  подготовленные размеры не требуют декодировать исходное изображение при каждом старте и
  сохраняют бюджет памяти.
- **Dependencies**: дополнительных runtime-крейтов нет.
- **Alternatives considered**: отдельные `.png` рядом с `.exe` (ломает переносимую сборку одним
  файлом).
