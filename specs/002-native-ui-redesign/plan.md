# План реализации: FreeSpace — переход на ui-sdk и минимальный визуальный язык

**Branch**: `002-native-ui-redesign` | **Date**: 2026-11-18 | **Spec**: [spec.md](./spec.md)

> **Это переписанный план.** Версия `plan.md` от 2026-11-16 описывала собственный
> (hand-rolled) UI-кит и декоративную тему «aurora/bento» (градиенты, подсветки, оранжевый +
> фиолетовый). Она **полностью заменяется** этим документом. Без изменений остаются
> IPC-контракты, модель безопасности (`freespace-ops`), CLI-паритет и офлайн-поставка из
> `spec.md` и `contracts/`. Меняются **слой представления** и состав экранов (11 вместо 24 —
> см. «UX-перекомпоновка» ниже):
> (1) компоненты строятся на **ui-sdk**, а не на собственном ките; (2) визуальный язык
> пересматривается в сторону **ясности, пространства и функционального цвета**.

> **Запись решения (v2, 2026-11-18).** Treemap (хитмап) удаляется из продукта полностью;
> исследование данных — только через **Дерево** со **встроенными прогресс-барами**. Экраны
> перекомпонованы с **24 до 11** и сгруппированы в сайдбаре по **6 группам**. Подробности — в
> разделе «UX-перекомпоновка» ниже; он заменяет все упоминания «24 экрана» и «Treemap» в плане.

## Summary

FreeSpace сохраняет ядро (Rust: сканирование, учёт размеров, операции, журнал, карантин) и
оболочку (Tauri 2 + React 19 + TypeScript + Vite) без изменений. Презентационный слой
переводится с собственного компонентного кита на **ui-sdk** (`@ui-sdk/react` + `@ui-sdk/core`,
уже установлены, версия `0.1.0-beta.10`): интерактивные компоненты (кнопки, поля, селекты,
диалоги, вкладки, меню, тултипы, тосты) берутся готовыми из ui-sdk, а специфичные для продукта
компоненты (виртуализированная таблица/дерево, палитра команд) строятся как
примитивы на `@ui-sdk/core` с теми же гарантиями клавиатуры, фокуса, ARIA и agent-bridge.

Одновременно пересматривается визуальная система: единый шрифт **JetBrains Mono**, просторная
сетка, минимальный функциональный цвет по правилу **60-30-10**, две полноценные темы (Light /
Dark) на сложных нейтральных оттенках (без чистых `#000000`/`#FFFFFF`), токены в **OKLCH**,
контраст **WCAG AA** (4.5:1 текст, 3:1 нетекстовое). Декоративные эффекты (градиенты,
радиальные подсветки, «приподнимание» кнопок, каскадные появления) удаляются: цвет и движение
остаются только там, где несут функцию.

## UX-перекомпоновка: отказ от Treemap и сокращение экранов

> **Запись решения (2026-11-18, v2).** Этот раздел дополняет и **заменяет** все места плана,
> где упоминаются «24 экрана» и «Treemap». Спецификация `spec.md` обновляется следом: FR-035…FR-043
> перепрофилируются под дерево со встроенными прогресс-барами, правятся FR-023 (состав экранов),
> SC-004 (30 fps дерева), SC-008/SC-016 (DPI и скриншоты) и Assumptions. До этой правки раздел —
> источник истины для слоя представления.

### Решение 1 — Treemap (хитмап) удаляется полностью

Карта-хитмап исключается из продукта. Данные исследуются только через **Дерево** со
**встроенными прогресс-барами**. Причины: карта плохо читается на плотных данных, дублирует
навигацию дерева, требует отдельную Canvas-реализацию (hit-testing, легенда, однотоновый ramp)
и противоречит принципу «чёткость важнее декора». Удаляются `TreemapCanvas`,
`treemap/palette`, `treemap/keyboard`, экран «Карта» и FR-035…FR-043. CLI-контракт `tree` не
меняется.

### Решение 2 — Встроенные прогресс-бары вместо отдельного экрана «Сканирование»

Прогресс больше не выносится на отдельный экран. Он показывается встроенно:

1. **«Обзор»** — строка прогресса под выбранным томом (текущий путь, скорость, объекты, отмена).
2. **Статус-бар оболочки** — сводный прогресс активной задачи и текущий путь.
3. **«Дерево»** — встроенные прогресс-бары у раскрываемых узлов: доля узла в родителе и в томе.

Пользователь видит постепенность и отменяет сканирование из любого места без переключения экрана.

### Решение 3 — Иконка приложения в сайдбаре

Бренд-блок сайдбара содержит **изображение приложения** (`/icon.png`), а не только
цветную плашку. Изображение декоративное и скрыто от скринридера (`aria-hidden="true"`
у контейнера, пустой `alt`).

### Решение 4 — Перекомпоновка экранов: 24 → 11, иерархия по группам

Близкие по смыслу экраны объединены; сайдбар получает **двухуровневую иерархию** — группы с
заголовками и экраны внутри.

| Группа | Экраны | Поглощённые экраны (из 24) |
|--------|--------|----------------------------|
| **Обзор** | Обзор | Диски + Сканирование (встроенный прогресс) |
| **Анализ** | Дерево · Анализ · Дубликаты | Дерево + Детали размера (карточка по наведению); Анализ = Крупнейшие файлы + Типы + Владельцы |
| **Очистка** | Очистка | Очистка + Снимки (вкладки) |
| **Операции** | Журнал · Шредер · Мониторинг записи | — |
| **Инструменты** | Инспекция · Файловые операции | Инспекция = Метаданные + Архивы + Разблокировка + Длинные пути; Файловые операции = Переименование + Права |
| **Система** | Настройки | Настройки + Elevation + О программе |

Экспорт отчёта — не отдельный экран, а **глобальное действие** (кнопка «Экспорт» на экранах,
порождающих данные: Дерево, Анализ, Дубликаты, Журнал).

**Итог: 11 экранов в 6 группах** (было 24). Как самостоятельные экраны упразднены: Карта,
Сканирование, Детали размера, Владельцы, Снимки, Экспорт, Elevation, О программе.

## 1. Принципы дизайна

Эти семь правил — источник истины для любого визуального решения и для ревью:

1. **Чёткость важнее декора.** Любое украшение, мешающее чтению данных, удаляется.
2. **Просторное пространство.** Отступы и «воздух» дают свободу движения и не склеивают данные.
3. **Минимальный функциональный цвет.** Цвет означает состояние или действие, а не настроение.
4. **Ясная типографическая иерархия.** Единая шкала, без случайных размеров и весов.
5. **Ненавязчивое целенаправленное взаимодействие.** Без «уловок»: подсветка, hover и движение
   только там, где помогают понять состояние.
6. **Выравнивание на уровне пикселей.** Сетка и базовые линии обязательны для всех элементов.
7. **Каждый элемент имеет причину существования.** Лишний элемент — дефект, а не деталь.

## 2. Дизайн-система

### 2.1 Цвет

Канон цветов — `ui/src/styles/tokens.css` и `themes.css`. Все компоненты обязаны использовать
только `var(--fs-*)`; скрипт `check:tokens` запрещает жёсткие цвета вне этих файлов. Бренд-тона
заданы в HEX (точно из палитры продукта); промежуточные ступени выводятся через
`color-mix(in oklch, …)`, что сохраняет плавные переходы OKLCH.

Требования палитры (обязательные):

1. Две полноценные темы: **Light** и **Dark** (плюс системная — наследуется из `spec.md`).
2. Без чистых `#000000`/`#FFFFFF` на больших поверхностях — палитра из пяти тонов на тему
   (тёмная: teal → cream; светлая: brown/olive → greige) с производными ступенями поверхностей.
3. Баланс **60-30-10**: 60 % — фон, 30 % — поверхности/карточки, 10 % — акцент и активные
   состояния.
4. Контраст текста и интерактивных элементов не ниже **WCAG AA** (4.5:1 текст, 3:1 крупный
   текст и границы/состояния). Проверяется автоматическим контраст-тестом.
5. Бренд-тона — HEX; производные оттенки — `color-mix(in oklch, …)`; прозрачность — только
   для линий, выделений и наложений.

#### 2.1.4 Правила использования цвета

- **Один акцент.** Единственный выразительный тон — `--fs-accent*`: кремовый `#fae8da` в тёмной
  теме (на фоне `#344b52`) и тёмно-оливковый `#5d5935` в светлой (на `#e8e1db`). Применяется к
  primary-кнопке, активному/выбранному состоянию, кольцу фокуса и ссылкам — это «10 %» правила
  60-30-10.
- **Семантические цвета** (`--fs-success/danger/warning/info`) — строго функциональны и
  приглушены под палитру: статус, результат операции, уровень риска. Никогда как украшение;
  всегда сопровождаются текстом и иконкой.
- **Поверхности несут 90 % интерфейса.** Уровни (bg → surface → raised → overlay) различаются
  светлотой в пределах палитры, а не добавлением цвета.
- **Контраст (проверено):** тёмная — текст 7.75:1, muted 6.08:1, subtle 6.01:1 к фону (и 4.59:1
  на raised); светлая — 10.32:1, 5.51:1, 4.92:1; семантика и акцентная пара ≥ 4.5:1 на
  surfaces/raised.
- **Скроллбар:** трек — `--fs-bg` (сливается с фоном), ползунок — производный от
  `--fs-text-subtle` и фона оттенок палитры.
- **Палитра прогресс-баров дерева** — полупрозрачная заливка строки узла в пределах палитры;
  выбранная строка выделяется акцентом и кольцом, а не радугой.
- **Прозрачность** — только для `--fs-line`, `--fs-selection` и наложений; основной текст и
  заливки — непрозрачные.

### 2.2 Типографика

Единый шрифт **JetBrains Mono** (все веса 400/500/600/700), без отдельного sans/display. Выбор
обоснован характером продукта: пути, размеры, таблицы и числа выигрывают от моноширинности и
табличных цифр; один шрифт устраняет «случайность» иерархии.

| Токен | Значение |
|-------|----------|
| `--fs-font-mono` | `"JetBrains Mono", "Cascadia Mono", "Consolas", ui-monospace, monospace` |
| `--fs-weight-regular` | `400` |
| `--fs-weight-medium` | `500` |
| `--fs-weight-semibold` | `600` |
| `--fs-weight-bold` | `700` |

Шкала кеглей (модульная, ratio ≈ 1.2, якорь 13px):

| Токен | Размер/интерлиньяж | Вес | Роль |
|-------|--------------------|-----|------|
| `--fs-text-2xs` | `11px / 15px` | 500 | Надзаголовки, подписи дерева, бейджи, kbd |
| `--fs-text-xs` | `13px / 17px` | 400 | Ячейки таблиц, плотные списки, метаданные |
| `--fs-text-sm` | `15px / 20px` | 400 | Вторичный текст, описания |
| `--fs-text-base` | `16px / 22px` | 400 | Основной текст, поля, формы |
| `--fs-text-md` | `19px / 26px` | 500 | Пункты списков, навигация, кнопки |
| `--fs-text-lg` | `23px / 30px` | 600 | Заголовки секций |
| `--fs-text-xl` | `27px / 34px` | 600 | Заголовки панелей |
| `--fs-text-2xl` | `33px / 40px` | 600 | Заголовок экрана (h1) |
| `--fs-text-3xl` | `40px / 46px` | 700 | Крупные числа/статистика |
| `--fs-text-4xl` | `48px / 54px` | 700 | Крупная статистика дашборда |

Правила:

- Числа и размеры всегда табличные (`font-variant-numeric: tabular-nums`; JetBrains Mono
  моноширинна по умолчанию).
- Надзаголовки секций — `2xs`, `500`, uppercase, letter-spacing `0.08em`.
- Один `h1` на экран (`2xl`); иерархия заголовков строго по шкале, без пропусков уровней.
- Размеры/пути/коды — моноширинным, не более чем на шаг меньше соседнего значения.
- JetBrains Mono поставляется **локально** (woff2, только нужные веса) в `ui/src/assets/fonts/`;
  без CDN и сетевых запросов. Fallback — системные моноширинные.

### 2.3 Интервал и ритм

Единая шкала отступов на сетке **8px** (полушаг 4px для микро-выравнивания):

| Токен | Значение | Токен | Значение |
|-------|----------|-------|----------|
| `--fs-space-1` | `4px` | `--fs-space-6` | `24px` |
| `--fs-space-2` | `8px` | `--fs-space-8` | `32px` |
| `--fs-space-3` | `12px` | `--fs-space-10` | `40px` |
| `--fs-space-4` | `16px` | `--fs-space-12` | `48px` |
| `--fs-space-5` | `20px` | `--fs-space-16` | `64px` |

Правила выравнивания:

- Внешние отступы кратны 8px; 4px — только для подгонки иконок/подписей к базовой линии.
- Текст сидит на базовой линии 4px; контейнеры выровнены по сетке 8px.
- Горизонтальный отступ страницы — 24px; вертикальный шаг между секциями — 32px.
- Плотность: comfortable (36px строки) / compact (30px) через `data-density`, без изменения сетки.
- Заголовок приложения — 56px, сайдбар — 240px (свёрнутый 64px), статус-бар — 28px.

### 2.4 Архитектура компоновки

**Структура страницы (сверху → снизу):**

1. Нативный заголовок окна Windows (системные кнопки — вне приложения).
2. Контентный заголовок: название экрана, контекстные действия (справа).
3. Контекстная строка: текущий том, состояние сканирования, активные задачи.
4. Основная область (primary section) — данные экрана.
5. Боковая панель деталей (details, справа) — там, где экран её требует.
6. Статус-бар (снизу): состояние, прогресс, уведомления.

**Система сетки:** 12 колонок, межколонник 24px, боковые поля 24px, контейнер до 1440px.
Сайдбар вне сетки (фиксированные 240/64px). Основная область делится на 12 колонок; карточки и
панели занимают целые числа колонок.

**Иерархия разделов:** экран → секция (заголовок `lg` + надзаголовок `2xs`) → панель/карточка
(`--fs-surface-raised` + `--fs-line`) → компонент. Секции отделяются 32px; внутри панели — 16px.

### 2.5 Радиусы, границы, тени, движение

| Группа | Значения |
|--------|----------|
| Радиусы | `--fs-radius-sm: 4px`, `md: 6px`, `lg: 8px`, `pill: 999px` |
| Границы | `1px solid var(--fs-line)`; сильная — `--fs-line-strong` |
| Тени | только функциональные: диалог/оверлей `--fs-shadow-overlay`; декоративные тени удалены |
| Слои | `--fs-z-sticky: 10`, `dropdown: 100`, `overlay: 200`, `dialog: 300`, `toast: 400`, `tooltip: 500` |
| Motion | `--fs-motion-fast: 120ms`, `--fs-motion-base: 180ms`, `--fs-ease: cubic-bezier(.2,.8,.2,1)`, `--fs-motion-reduced: 0ms` |

Правила: переходы только для функциональных изменений состояния (открытие/закрытие, hover,
фокус); `prefers-reduced-motion: reduce` или `reduced_motion=on` отключают необязательные
переходы. Никаких каскадных появлений, count-up и «приподнимания» кнопок.

## 3. Архитектура компонентов (ui-sdk)

Интерактивное поведение (клавиатура, фокус, ARIA, dismissal, popups, agent-bridge) даёт ui-sdk;
приложение задаёт только разметку и стили через токены. Стилизация — по `data-slot` и
состояниям (`data-open`, `data-pressed`, `data-highlighted`, …) и CSS-переменным, без
сгенерированных id.

В глобальном стилевом файле первой строкой объявляется `@layer ui-sdk;` (выше любых импортов),
чтобы собственные стили всегда побеждали.

### 3.1 Замена собственного кита → компоненты ui-sdk

| Текущий компонент | Компонент ui-sdk (entry) |
|-------------------|---------------------------|
| `Button` / `IconButton` | `@ui-sdk/react/button` (`Button`) |
| `Field` / `Fields` | `@ui-sdk/react/field` (`Field`, `FieldLabel`, `FieldDescription`, `FieldError`) |
| `SearchField` | `Field` + `@ui-sdk/react/input`, либо `@ui-sdk/react/combobox` |
| `Select` | `@ui-sdk/react/select` |
| `Combobox` | `@ui-sdk/react/combobox` |
| `Segmented` | `@ui-sdk/react/segmented-control` или `toggle-group` |
| `Tabs` | `@ui-sdk/react/tabs` |
| `Toggle` | `@ui-sdk/react/switch` (или `toggle`) |
| `Checkbox` | `@ui-sdk/react/checkbox` |
| `Radio` | `@ui-sdk/react/radio` (radio-group) |
| `Tooltip` | `@ui-sdk/react/tooltip` |
| `Dialog` | `@ui-sdk/react/dialog` |
| `ConfirmDialog` | `@ui-sdk/react/alert-dialog` |
| `Toast` / `Feedback` | `@ui-sdk/react/toast` + `OverlayHost` (`@ui-sdk/react/overlays`) |
| `ContextMenu` | `@ui-sdk/react/menu` (или `trigger-menu`) |
| `CommandPalette` | `@ui-sdk/react/command` |
| `Progress` | `@ui-sdk/react/progress` |
| `Meter` | `@ui-sdk/react/meter` |
| Разделители | `@ui-sdk/react/separator` |
| Прокрутка списков | `@ui-sdk/react/scroll-area` |
| SplitPane | `@ui-sdk/react/resizable` |

### 3.2 Примитивы на `@ui-sdk/core` (чего ui-sdk не поставляет)

- **`DataTable` / `TreeTable`** — виртуализированная таблица и дерево. ui-sdk не имеет
  table/data-grid, поэтому это собственный примитив: `createGridFocus`/`createTreeCollection`
  + `createSelection` + `createTypeahead` из `@ui-sdk/core`, виртуализация — существующий
  `@tanstack/react-virtual`. Рендер — через `createParts` из `@ui-sdk/react/primitive`.
- **`TreeRow`** — строка виртуализированного дерева с иконкой типа и полупрозрачным
  встроенным прогресс-баром; управление фокусом и клавиатурой — примитив на `@ui-sdk/core`
  (roving focus), чтобы дерево было доступно и видимо для agent-bridge.
- **`Badge` / `Chip` / `Kbd` / `Card` / `EmptyState` / `ErrorState` / `Banner`** — презентационные;
  строятся как простые обёртки без интерактивности (интерактивные варианты — `Toggle`/`Button`).

### 3.3 Agent-bridge

`createAgent()` из `@ui-sdk/react/agent` подключается один раз при старте. Все интерактивные
элементы получают имя (label/title/`aria-label`); разрушающие действия размечаются
`data-agent-confirm`. Это даёт доступность для экранных дикторов и возможность скриптовать UI
без обхода безопасности: изменения проходят через те же колбэки и могут быть отклонены
(`details.cancel()`, `allow`).

**Primary Dependencies**:

  `package.json`; версия фиксируется — beta, обновление только с ревью changelog).
- Таблицы/виртуализация: `@tanstack/react-table` 8.x, `@tanstack/react-virtual` 3.x.
- Состояние: `zustand` 5.x (stores на экран + shell-store).
- Иконки: `lucide-react` 0.468 (локально, единый набор).
- Шрифт: **JetBrains Mono** — локальные woff2 в `ui/src/assets/fonts/` (веса 400/500/600/700).
- Локализация: `locales/ru.toml`/`en.toml` + `scripts/gen-i18n.mjs`.
- Тесты: `vitest`, RTL, `jsdom`, `@playwright/test`, `@axe-core/playwright`, `tauri-driver`.
- Rust: `tauri`, существующие `freespace-core/platform/scan/ops/analysis/report/cli` +
  `freespace-app`.

**Storage**: без изменений — каталог `data` рядом с exe; WebView2-профиль в `data/webview2`;
`localStorage`/`IndexedDB` вне `data` не используются.

**Testing**: `cargo fmt/clippy/test` (ядро), `vitest`+RTL (компоненты/экраны), Playwright

**Target Platform**: Windows 10 21H2+/Windows 11 x64; WebView2 (офлайн) не ниже Chromium 111
(для `oklch()`).

**Performance Goals**: отклик ≤ 200 мс; дерево ≥ 30 fps на 10 млн узлов; память ≤ 4 ГБ;
первый экран ≤ 3 с; анализ 8 ТБ ≤ 60 с; события throttle 10–20 Гц. Без изменений.

**Constraints**: офлайн/без телеметрии; CSP `default-src 'self'` + nonce для CSS ui-sdk
(meta `csp-nonce` / `html.cspNonce` в Vite); WinAPI только в `freespace-platform`; разрушающие
операции только через `freespace-ops`; один GUI (egui удалён); CLI-контракт неизменен.

**Scale/Scope**: 11 экранов в 6 группах, RU/EN, 3 режима темы, DPI 100–200%, до 10 млн узлов;
один GUI + CLI.

## 8. Complexity Tracking

| Решение | Зачем | Отклонённая альтернатива |
|---------|-------|--------------------------|
| ui-sdk вместо собственного кита | Готовые гарантии клавиатуры/фокуса/ARIA/agent-bridge; меньше кода и тестов на поведение. | Собственный кит дублирует поведение и доступность; дороже поддерживать. |
| Примитивы DataTable/TreeRow на `@ui-sdk/core` | ui-sdk не поставляет table/canvas; поведение фокуса/выбора берётся из core, рендер остаётся продукту. | Писать ARIA/focus вручную — риск багов доступности. |
| JetBrains Mono как единственный шрифт | Данные/пути/таблицы выигрывают от моноширинности; одна шкала без случайности. | Пара sans+mono вносит вторую иерархию и не даёт табличных цифр для UI-текста. |
| OKLCH-токены | Современное пространство, плавные переходы; требование палитры. | HEX-only уступает в управлении светлотой и консистентности. |
| Локальная поставка шрифта | Офлайн (принцип VII). | CDN/webfont нарушает офлайн-требование. |
| Полупрозрачная заливка прогресс-бара дерева | Минимальный функциональный цвет; доля читается светлотой, акцент — для выделения. | 10 градиентов/радуга — декоративный цвет, противоречит принципу 3. |

## 9. Post-Design Constitution Re-Check

После этапов 0–2 повторно проверяется:

- все разрушающие действия проходят через `freespace-ops` и `alert-dialog` с `data-agent-confirm`;
- контраст 4.5:1 (текст) / 3:1 (нетекстовое) в обеих темах на всех 11 экранах;
- CSP с nonce не блокирует CSS/ui-sdk и не допускает сетевых запросов;
- `@layer ui-sdk` объявлен первым, собственные стили побеждают;
- шрифт JetBrains Mono поставляется локально, без CDN;
- виртуализация и Canvas укладываются в бюджеты 200 мс / 30 fps / 4 ГБ;
- agent-bridge не обходит безопасность (`allow`, `details.cancel()`).

## 10. Risks and Mitigations

| Риск | Мера |
|------|------|
| `@ui-sdk/*` — beta, API может меняться | Версия зафиксирована; обновление только с ревью changelog и тестами. |
| CSP блокирует CSS ui-sdk | Meta `csp-nonce` / `html.cspNonce`; `@layer ui-sdk`; тест CSP в E2E. |
| WebView2 старше Chromium 111 не знает `oklch()` | Offline-runtime ≥ 111; HEX-fallback для старых сред; проверка версии. |
| Миграция ломает существующие экраны | Замена компонент за компонентом; старые тесты остаются контрактом до замены. |
| Регрессия визуального языка | Перегенерация эталонов после стабилизации; `check:tokens` блокирует жёсткие цвета. |
| Шрифт увеличивает размер поставки | Подмножество глифов, только нужные веса; замер в research. |
| Снижение плотности (просторность) против данных | Comfortable/compact через `data-density`; таблицы остаются виртуализированными. |
| Доступность при custom-примитивах | `@ui-sdk/core/testing` (клавиатура/фокус/ARIA) + axe на всех экранах. |
