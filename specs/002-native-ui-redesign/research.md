# Research: FreeSpace — технические решения для интерфейса 002

**Feature**: `002-native-ui-redesign` | **Date**: 2026-11-16

Все открытые решения из `docs/ui-redesign-plan.md` разрешены ниже в формате «решение —
обоснование — альтернативы». Версии зависимостей фиксируются в `Cargo.lock` и
`package-lock.json`; в тексте указаны совместимые диапазоны.

## 1. GUI-стек и полная замена egui

- **Decision**: Tauri 2.x + React 18.3 + TypeScript 5.6 + Vite 6.x. Новый клиент
  `apps/freespace-desktop` полностью заменяет `apps/freespace-gui`; egui-зависимости и старые
  views удаляются в рамках 002. Второй UI, beta-флаг и side-by-side не создаются.
- **Rationale**: стек уже утверждён в `docs/ui-redesign-plan.md` и макете `web/`; он даёт
  точный перенос языка интерфейса, CSS-темы, DOM-доступность, Playwright и большую экосистему
  компонентов. Конституция допускает Tauri при обоснованной необходимости веб-технологий, а
  вся нативная функциональность остаётся в Rust. Старый UI не выпускался, поэтому его
  параллельная поддержка не имеет ценности и только удваивает стоимость тестов и упаковки.
- **Alternatives considered**: остаться на egui (нет нужного визуального контроля, CSS-тем и
  DOM-доступности); Slint (меньше экосистема и хуже перенос макета); WinUI 3 (тяжёлая
  интеграция с Rust и C++/C#); React 19 (не соответствует утверждённому макету и добавляет
  миграционный риск без выгоды для задачи).

## 2. Структура репозитория и удаление старого GUI

- **Decision**: единственный GUI-крейт — `apps/freespace-desktop` с бинарём
  `freespace-gui.exe`; каталог `apps/freespace-gui` удаляется, его исходники остаются в
  истории git как источник паритета. `Cargo.toml` workspace и `default-members` обновляются
  одновременно, чтобы в сборке никогда не было двух GUI.
- **Rationale**: полная замена без промежуточной двойной поставки. Имя бинаря сохраняет
  ярлыки, скрипты, установщик и записи контекстного меню. История git достаточна для сверки
  24 экранов при переносе.
- **Alternatives considered**: оставить `apps/freespace-gui` как reference-крейт (нарушает
  решение о полной замене и создаёт мёртвый код); переименовать каталог без смены бинаря
  (ломает внешние сценарии); вести новый клиент рядом (отклонено владельцем продукта).

## 3. Прикладной слой `freespace-app`

- **Decision**: новый крейт `crates/freespace-app` содержит прикладные сервисы, DTO,
  пагинацию, агрегацию Treemap, миграцию UI-настроек и оркестрацию задач. Tauri-команды —
  тонкие адаптеры: валидация входа, вызов сервиса, сериализация, события. WinAPI в
  `freespace-app` отсутствует.
- **Rationale**: 24 экрана не должны копировать логику egui-views; команды не должны
  превращаться в бизнес-логику. Отдельный крейт тестируется без Tauri и переиспользуется
  CLI/будущими фронтендами. Домен остаётся в `freespace-core`, операции — в `freespace-ops`.
- **Alternatives considered**: логика прямо в Tauri-командах (дублирование, сложные тесты);
  всё в `freespace-core` (размывает домен и тянет UI-DTO в ядро); всё в TypeScript
  (нарушает владение логикой и безопасность).

## 4. IPC: команды, события и транспорт

- **Decision**: управляющие вызовы — типизированные Tauri-команды с JSON-схемами; большие
  наборы (страницы дерева, тайлы Treemap) — компактные DTO, при необходимости бинарный
  `tauri::ipc::Response`; прогресс и изменения — Tauri-события с throttle 10–20 Гц. Каждая
  длительная задача имеет `task_id`, состояние, прогресс и `cancel(task_id)`.
- **Rationale**: JSON удобен для типизации и тестов; бинарный ответ снижает overhead на
  больших страницах. События не должны становиться вторым каналом данных: они передают
  прогресс/инвалидацию, а данные запрашиваются страницами.
- **Alternatives considered**: один WebSocket/HTTP-сервер внутри приложения (лишняя
  поверхность атаки и сеть); полный JSON дерева (не проходит бюджет); polling без событий
  (лишняя нагрузка и задержки).

## 5. Пагинация и стабильные курсоры

- **Decision**: курсорная пагинация с непрозрачным `cursor`, кодирующим ключ сортировки и
  `node_id`; размер страницы по умолчанию 500, максимум 2000. Ответ содержит `rows`,
  `next_cursor`, `total_estimate` (если известен) и `generation`/`snapshot_id`. Смена
  сортировки/фильтра сбрасывает курсор; устаревший курсор возвращает `stale_cursor`, и UI
  перезапрашивает первую страницу.
- **Rationale**: offset-пагинация на 10 млн узлов деградирует и даёт дубликаты при
  изменениях. Курсор стабилен, не требует полного счётчика и хорошо работает с
  виртуализацией. `generation` защищает от смешивания данных разных сканирований.
- **Alternatives considered**: offset/limit (медленно и нестабильно); отдавать всё дерево
  (запрещено бюджетом); keyset только по имени (нестабильно при дубликатах).

## 6. Treemap: Canvas и раскладка в Rust

- **Decision**: алгоритм squarified treemap переносится в `freespace-app` (UI-агностичная
  геометрия). Tauri-команда `treemap_tiles` получает `node_id`, размеры viewport, метрику,
  глубину и порог пикселей, агрегирует мелкие узлы и возвращает ограниченный набор плиток
  (`id`, `rect`, `depth`, `size`, `color_key`, `label`, `is_aggregate`). React рисует плитки
  на Canvas 2D с учётом `devicePixelRatio`; hit-testing — по массиву плиток или quadtree;
  перерисовка только по dirty-флагу и `requestAnimationFrame`.
- **Rationale**: Canvas выдерживает десятки тысяч плиток, не создаёт DOM на каждый узел и
  даёт стабильные 30 fps. Раскладка в Rust переиспользует существующий алгоритм и не
  дублируется в JS; агрегация в Rust не передаёт миллионы узлов.
- **Alternatives considered**: SVG (тяжело при больших наборах); DOM-плитки (layout/paint
  дорого); WebGL (избыточная сложность и риск для доступности); раскладка в TypeScript
  (дублирование алгоритма и JS CPU-нагрузка).

## 7. Таблицы и виртуализация

- **Decision**: `@tanstack/react-table` для модели столбцов, видимости, порядка и ширины;
  `@tanstack/react-virtual` для виртуализации строк и, при необходимости, столбцов.
  Сортировка, фильтрация и поиск — серверные; таблица запрашивает страницы и не держит весь
  набор в памяти.
- **Rationale**: зрелые, небольшие библиотеки без тяжёлого UI-фреймворка; хорошо работают с
  курсорной пагинацией; позволяют сделать единый `DataTable` для 24 экранов. Сортировка на
  сервере сохраняет согласованность сумм.
- **Alternatives considered**: собственный виртуализатор (больше кода и крайних случаев);
  AG Grid (тяжёлая лицензия и стили); MUI DataGrid (тяжёлый UI-фреймворк); Ant Design
  (избыточный дизайн-язык).

## 8. Состояние представления

- **Decision**: Zustand 5.x. Отдельные stores: `shellStore` (экран, тема, язык, уведомления),
  `scanStore` (задача, прогресс), `selectionStore` (выделение, фильтры) и фабрика
  per-screen stores. Данные страниц хранятся в store экрана с `generation` и `cursor`;
  события обновляют только затронутые срезы.
- **Rationale**: минимальный boilerplate, точечные подписки и отсутствие провайдеров; хорошо
  подходит для событийного desktop-приложения. Глобального кеша данных нет — источник истины
  Rust, а страницы короткоживущие.
- **Alternatives considered**: React context/useReducer (частые ререндеры и prop drilling на
  24 экранах); Redux Toolkit (тяжелее для задачи); TanStack Query (полезен, но добавляет
  второй слой кеша и конфликтует с событийной моделью; можно добавить позже при
  необходимости).

## 9. Стили и дизайн-токены

- **Decision**: CSS custom properties в `styles/tokens.css` + CSS Modules для компонентов.
  Тема задаётся `:root[data-theme="dark"|"light"]`; системная — через `prefers-color-scheme`
  и сохранённую настройку. Запрет жёстких цветов проверяется линтом/скриптом.
- **Rationale**: нулевой runtime, быстрая смена темы, полный контроль над CSS и отсутствие
  конфликтов с CSP. CSS Modules дают локальные имена и не требуют CSS-in-JS.
- **Alternatives considered**: Tailwind (труднее удержать токены и запрет хардкода);
  styled-components/emotion (runtime и CSP-риски); vanilla-extract (дополнительная сборка);
  глобальный CSS без модулей (коллизии на 24 экранах).

## 10. Шрифты и иконки

- **Decision**: системные шрифты `Segoe UI Variable`, `Segoe UI`, `Cascadia Mono` для
  моноширинного текста; `lucide-react` 0.468 с именованными импортами. Никаких CDN и
  загружаемых шрифтов.
- **Rationale**: соответствует Windows, не требует сети и лицензионных вложений, хорошо
  масштабируется на 100–200% DPI. Lucide уже используется в макете.
- **Alternatives considered**: встроенные веб-шрифты (размер и лицензии); иконочный шрифт
  (хуже доступность); SVG-спрайт (больше ручной работы).

## 11. Тема без вспышки при старте

- **Decision**: Rust читает `settings.toml` до создания окна и передаёт тему, язык и
  reduced-motion через `initialization_script` Tauri (`window.__FREESPACE_BOOT__`).
  Синхронный `public/boot.js` в `<head>` до CSS выставляет `data-theme` и `lang`. В браузере
  без Tauri `boot.js` использует `prefers-color-scheme`.
- **Rationale**: `localStorage` запрещён, а асинхронный IPC после первой отрисовки даёт
  вспышку. Инициализационный скрипт выполняется WebView2 до загрузки страницы и не требует
  сети.
- **Alternatives considered**: хранить тему в localStorage (нарушает FR-011); ждать IPC и
  переключать тему после монтирования (вспышка); отдельная нативная тема окна (не покрывает
  контент).

## 12. Профиль WebView2 в каталоге `data`

- **Decision**: до создания webview устанавливается `WEBVIEW2_USER_DATA_FOLDER` в
  `<exe_dir>\data\webview2` (или эквивалентный `data_directory` Tauri, если доступен в
  выбранной версии). Дополнительно задаются аргументы, отключающие фоновые сетевые
  компоненты Edge. Путь проверяется на запись; при ошибке приложение сообщает о проблеме и
  работает без сохранения профиля.
- **Rationale**: по умолчанию WebView2 создаёт профиль в `%LOCALAPPDATA%`, что прямо
  нарушает FR-093/FR-106 и конституцию. Локальный профиль также упрощает портативность и
  удаление следов.
- **Alternatives considered**: оставить профиль по умолчанию (нарушение); отключить профиль
  полностью (невозможно для WebView2); переносить профиль после старта (поздно и рискованно).
- **Результат spike (T031)**: Tauri 2.11.6 предоставляет `WebviewWindowBuilder::data_directory`
  и `additional_browser_args`, поэтому переменная окружения не нужна: окно создаётся в
  `setup`, профиль размещается в `data/webview2`, а фоновые компоненты Edge отключаются
  аргументами. Проверено сборкой и тестами `freespace-desktop`; запись профиля проверяется
  при первом запуске окна.

## 13. Настройки и миграция без localStorage

- **Decision**: UI-настройки — новая секция `[ui]` в `data/settings.toml` (тема, язык,
  плотность, единицы, reduced motion, последний экран, видимость столбцов); состояние окна —
  `data/ui-state.toml` (размер, положение, maximized, монитор). Перед миграцией создаётся
  резервная копия `settings.toml.bak`; миграция версионируется и идемпотентна. React не
  использует `localStorage`/`IndexedDB`.
- **Rationale**: единое хранилище и один владелец записи (Rust); настройки переживают
  переустановку и работают в портативной сборке; нет скрытых данных в профиле WebView2.
- **Alternatives considered**: localStorage (нарушение и потеря при очистке профиля);
  отдельный JSON в `%APPDATA%` (запрещён); хранить только в памяти (потеря настроек).

## 14. Локализация: один источник TOML

- **Decision**: `locales/ru.toml` и `locales/en.toml` остаются единственным источником.
  `ui/scripts/gen-i18n.mjs` (Node + `smol-toml`) разворачивает вложенные таблицы в плоские
  ключи, генерирует `ui/src/i18n/generated/ru.ts`, `en.ts` и `keys.ts` (union ключей).
  Сгенерированные файлы коммитятся; CI проверяет отсутствие diff. Rust продолжает
  использовать `rust-i18n` с теми же TOML.
- **Rationale**: нет двух наборов строк, ключи типизированы, missing-key ловится тестом,
  переключение языка мгновенное. Генератор не тянет тяжёлый i18n-фреймворк.
- **Alternatives considered**: отдельные JSON-каталоги вручную (рассинхронизация); отдавать
  строки через IPC (нет типизации и лишний runtime-слой); Fluent (мощнее, но избыточен для
  двух языков).

## 15. Навигация, глубокие ссылки и один экземпляр

- **Decision**: состояние экрана — типизированный enum в `shellStore`, без URL-роутера.
  Последний экран сохраняется; глубокие ссылки приходят из CLI/контекстного меню и
  передаются через single-instance плагин Tauri. Повторный запуск активирует существующее
  окно.
- **Rationale**: десктопному приложению не нужен URL; enum даёт типобезопасность и простую
  сериализацию. Single-instance сохраняет один каталог `data` и один журнал.
- **Alternatives considered**: React Router (лишняя абстракция для десктопа); несколько
  экземпляров (конфликт журнала/карантина); глубокая ссылка через сеть (офлайн-запрет).

## 16. Безопасность Tauri

- **Decision**: CSP `default-src 'self'; connect-src ipc: http://ipc.localhost;
  img-src 'self' data:; style-src 'self' 'unsafe-inline'; script-src 'self'`; без remote
  URL. Минимальные capabilities: `core:default` и точечные window/event разрешения; плагины
  fs/shell/http не подключаются. `withGlobalTauri: false`, devtools выключены в release,
  `dangerousDisableAssetCspModification` не используется. Все пути валидируются и
  канонизируются в `security.rs`/`freespace-app`.
- **Rationale**: React не должен получить доступ к ФС или сети; узкая поверхность атаки
  критична для утилиты, которая видит весь диск. `style-src 'unsafe-inline'` нужен для
  React style-атрибутов и не открывает сеть.
- **Alternatives considered**: отключить CSP (недопустимо); подключить fs/shell-плагины для
  удобства (обходит `freespace-ops`); `withGlobalTauri: true` (лишняя глобальная поверхность).

## 17. Поставка WebView2

- **Decision**: собственный fixed runtime WebView2 входит и в установщик, и в портативную
  сборку; версия фиксируется при релизе. Если измеренный размер установщика превышает
  согласованный бюджет, установщик переключается на `offlineInstaller`, а портативная сборка
  сохраняет fixed runtime. Решение и размеры фиксируются в отчёте spike.
- **Rationale**: установка и запуск обязаны работать без сети на чистой Windows 10, где
  WebView2 может отсутствовать. Fixed runtime даёт одинаковое поведение и не зависит от
  обновлений Edge. `offlineInstaller` — допустимый компромисс по размеру.
- **Alternatives considered**: требовать системный WebView2 (риск отказа); download
  bootstrapper (нарушает офлайн); MSIX с зависимостью на Edge (ограничения установки).

## 18. Установщик: Tauri NSIS вместо Inno

- **Decision**: основной установщик — Tauri NSIS; Inno Setup выводится из поставки после
  переноса сценариев. NSIS-хуки вызывают `freespace-gui.exe context-menu uninstall`, удаляют
  `data` и ярлыки; portable ZIP собирается отдельно. Подпись — через Tauri `signCommand` или
  `certificateThumbprint`.
- **Rationale**: один установщик, нативная поддержка WebView2, Tauri-артефактов и подписи;
  меньше дублирования и расхождений. Сценарии Inno переносятся в NSIS-хуки и тестируются.
- **Alternatives considered**: оставить Inno как обёртку (два установщика и двойная
  поддержка); MSI (хуже кастомизация удаления `data`); MSIX (ограничения реестра и
  контекстного меню).

## 19. Имя исполняемого файла и продукт

- **Decision**: продукт — `FreeSpace`, GUI-крейт — `freespace-desktop`, бинарь —
  `freespace-gui.exe`. Ярлыки, скрипты, контекстное меню и установщик продолжают работать.
- **Rationale**: сохраняет совместимость внешних сценариев и не создаёт второй продукт.
- **Alternatives considered**: `freespace-desktop.exe` (ломает ярлыки и документацию);
  `freespace.exe` (конфликт с CLI); переименование после релиза (лишняя миграция).

## 20. Тестирование

- **Decision**: Rust — unit/integration для `freespace-app`, команд, валидации, сериализации
  и миграции настроек; frontend — Vitest + RTL; Playwright на Vite-сборке с mock-транспортом;
  Tauri E2E — `tauri-driver` + WebdriverIO на Windows; доступность — `@axe-core/playwright` +
  Narrator; визуальная регрессия — Playwright screenshots с фиксированными шрифтами, DPI и
  допусками; network guard — перехват запросов и проверка CSP.
- **Rationale**: разные слои требуют разных инструментов; mock-транспорт позволяет быстро и
  стабильно проверять 24 экрана, а Tauri E2E подтверждает реальный IPC и упаковку.
- **Alternatives considered**: только ручные проверки (не масштабируется); только E2E
  (медленно и нестабильно); Cypress (хуже поддержка WebView2/Windows).

## 21. Производительность и измерения

- **Decision**: синтетический генератор дерева на 10 млн узлов в Rust; бенчмарки ядра
  остаются; UI-замеры — Playwright Performance API для кадров/отклика, счётчики процессов
  Windows для памяти, E2E-сценарии на контрольном VHD. Бюджеты: 200 мс, 30 fps, 4 ГБ, 3/5 с.
- **Rationale**: измеримые ворота до партий 3+; синтетика воспроизводима и не трогает
  реальные данные. Память считается по всему дереву процессов, а не только по Rust.
- **Alternatives considered**: замеры на реальном диске пользователя (запрещены); только
  ручная оценка (не objective); микробенчмарки без UI (не отражают WebView).

## 22. Доступность

- **Decision**: нативная DOM-семантика (кнопки, таблицы, деревья, диалоги), ARIA только где
  нужно, управление фокусом, клавиатурные сокращения, объявления через `aria-live`,
  `prefers-reduced-motion`, `prefers-contrast`. Narrator проверяется вручную.
- **Rationale**: WebView2 предоставляет UIA; правильная семантика даёт доступность без
  отдельного слоя. Автоматические проверки не заменяют Narrator.
- **Alternatives considered**: canvas-only интерфейс (недоступен); accesskit (для egui, не
  нужен); ARIA на каждый элемент (шум для диктора).

## 23. Ошибки, логи и наблюдаемость

- **Decision**: единый конверт ошибки `{ code, category, message_key, details,
  retryable, task_id? }`; React error boundary на экран и на оболочку; локальные логи
  `data/logs/ui.log` с ротацией; без телеметрии. Ошибки команд логируются на стороне Rust,
  UI показывает локализованное сообщение и связь с журналом.
- **Rationale**: пользователь видит понятное сообщение, поддержка — код и детали; данные не
  покидают машину. Границы ошибок не дают одному экрану уронить оболочку.
- **Alternatives considered**: показывать сырой текст Rust (плохо локализуется и раскрывает
  внутренности); телеметрия (запрещена); только консоль (недиагностируемо).

## 24. Окно, заставка и native chrome

- **Decision**: нативное окно Windows с системным заголовком и кнопками; внутри —
  собственный header контента. Заставка показывается до готовности UI и скрывается после
  первого кадра; состояние окна сохраняется в `ui-state.toml`.
- **Rationale**: нативный заголовок бесплатно даёт доступность, системное меню, поведение
  Snap и корректность на 100–200% DPI. Собственный header сохраняет визуальный язык макета
  без переизобретения кнопок окна.
- **Alternatives considered**: полностью frameless (больше кода, риск доступности и DPI);
  стандартная заставка без кастомного splash (менее цельно); запоминать состояние в
  localStorage (запрещено).

## 25. Сборка и CI

- **Decision**: два независимых задания CI на `windows-latest`: Rust (`fmt`, `clippy -D
  warnings`, `test`, бенчмарки по расписанию) и frontend (`npm ci`, `typecheck`, `lint`,
  Vitest, Playwright, visual, axe). Tauri E2E и упаковка — отдельное задание с кэшем
  зависимостей. Генерация i18n проверяется на отсутствие diff. Кэш — `Swatinem/rust-cache` и
  `actions/setup-node` с `npm` cache.
- **Rationale**: быстрые обратные связи и независимые ворота; Windows обязателен для WebView2,
  путей и DPI. Проверка генерации не даёт каталогам разойтись.
- **Alternatives considered**: один общий job (медленно); Linux-сборка frontend (не проверяет
  WebView2); пропуск визуальных тестов в CI (регрессии).

- **Runtime frontend (6)**: `react`, `react-dom`, `zustand` (состояние), `@tanstack/react-table` и
