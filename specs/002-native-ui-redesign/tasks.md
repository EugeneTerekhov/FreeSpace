# Задачи: FreeSpace — UX-перекомпозиция (11 экранов, без Treemap)

**Input**: Документы проектирования из `/specs/002-native-ui-redesign/`

**Prerequisites**: [plan.md](./plan.md) («UX-перекомпоновка»), [spec.md](./spec.md),

## Статус этого плана

Это **новый план** для фичи 002. Он заменяет прежний 24-экранный список задач.

- До перекомпоновки в репозитории был **24-экранный** Tauri 2 + React UI с Canvas-Treemap (`ui/src/screens/`:
  `Dashboard`, `Scan`, `Treemap`, `TopFiles`, `Types`, `Owners`, `Snapshots`, `Export`,
  `Elevation`, `About`, …) и соответствующие Rust-крейты/Tauri-команды. Он — исторический
  baseline; часть задач ниже опирается на него.
- Продукт переводится на **11 экранов в 6 группах**, без Treemap, с группированным сайдбаром,
  иконкой приложения, иконками типов и встроенными прогресс-барами в дереве.
- Референс новой компоновки — прототип `apps/freespace-desktop/ui/demo-next/` (untracked).
  Прототип **не является** продуктовой реализацией; после переноса в `src/` он удалён (T104).
- `[x]` ставится только после внедрения в `src/`, тестов и зелёных проверок (конституция,
  принцип V). Всё, что сейчас живёт лишь в `demo-next/`, **не отмечено**.

> **Состояние внедрения (2026-11-18).** Перекомпоновка выполнена: реестр 11 экранов и 6 групп,
> группированный сайдбар с иконкой приложения, новые токены и монотипографика, «Обзор» со
> встроенным сканированием, «Дерево» со встроенными полосами и деталями размера, вкладки
> Анализ/Очистка/Инспекция/Файловые операции/Настройки, глобальный экспорт, удалённый Treemap
> (фронтенд, Tauri-команды, DTO, фикстуры, бенчмарк). Прототип `demo-next/` удалён (T104).
> Проверки: `npx tsc --noEmit`, `npm run lint`, `check:tokens`, `check:i18n`, `check:network`,
> `npm run test:unit` (29 файлов / 185 тестов), Playwright E2E (55 сценариев) и axe (24 теста,
> 11 экранов × 2 темы + вкладки) — зелёные; `cargo check --workspace --all-targets`,
> `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings` — чистые.
> Открыты задачи, требующие визуальных эталонов и ручной приёмки (T100, T102, T103, T105).

**Tests**: тест-первый подход для критических модулей; UI — Vitest/RTL, Playwright, axe,
визуальная регрессия, Tauri E2E.

**Format**: `[ID] [P?] [Группа/Экран] Description`

- **[P]** — можно параллельно (разные файлы, нет зависимостей).
- **[Группа]** — Обзор / Анализ / Очистка / Операции / Инструменты / Система или ID экрана.
- В описании указан точный путь к файлу.

## Path Conventions

- Workspace-крейты: `crates/<name>/src/`
- GUI Rust: `apps/freespace-desktop/src-tauri/src/` (в задачах `src-tauri/...`)
- GUI React: `apps/freespace-desktop/ui/src/` (в задачах `ui/...`)
- Тесты frontend: `apps/freespace-desktop/ui/tests/`
- Tauri E2E: `apps/freespace-desktop/ui/tests/tauri/`
- Контракты и фикстуры: `specs/002-native-ui-redesign/contracts/`
- Локализация: `locales/`

## Dependencies & Execution Order

- **Phase 0** — уже в коде; на неё опирается всё остальное.
- **Phase 1** — после Phase 0; блокирует экраны (нужен реестр 11 экранов и группы).
- **Phase 2–8** — после Phase 1; между собой в основном параллельны по файлам.
- **Phase 9** — после Phase 3 и Phase 4 (Treemap больше не нужен) и до финальных эталонов.
- **Phase 10** — после Phase 2–9.

## Within Each Screen

- Сначала тест (Vitest/RTL или Rust), затем реализация.
- Существующие 24-экранные реализации переиспользуются как источник логики, но раскладка и
  навигация приводятся к 11-экранной компоновке.
- Визуальные эталоны — после стабилизации экрана.

## Parallel Opportunities

- Phase 1: T010, T011, T012 — разные файлы; T013 после них.
- Phase 2–8: экраны независимы по файлам после Phase 1.
- Phase 9: удаление Treemap можно вести параллельно с Phase 4–8.
- Phase 10: тесты/эталоны/паритет — параллельно, финальный прогон последовательный.

## Notes

- `[P]` — разные файлы, нет зависимостей.
- Все разрушающие сценарии — только на временных каталогах/VHD; admin-тесты за
  `FREESPACE_ADMIN_TESTS=1`.
- 0 сетевых вызовов, 0 хардкод-цветов, 0 строк вне локализации — блокирующие проверки.
- Коммиты — Conventional Commits; одна задача или логическая группа на коммит.
