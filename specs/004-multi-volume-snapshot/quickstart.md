# Quickstart: Мультитомный снимок

**Feature**: `004-multi-volume-snapshot` | **Date**: 2026-11-20

## Предварительные условия

- Windows 10 21H2+ или Linux x86_64; приложение собрано из ветки `004-multi-volume-snapshot`.
- Для Windows-сценариев желательны два тестовых тома (VHD/VHDX), чтобы не трогать рабочие диски.
- Для Linux-сценариев — два каталога или две точки монтирования на временной файловой системе.
- Реальные пользовательские файлы не изменяются; удаление проверяется только на временных данных.

## 1. GUI: два тома в одном дереве

1. Запустить приложение и открыть «Обзор».
2. Нажать на карточки двух доступных томов и нажать «Анализировать».
3. Дождаться завершения.

**Ожидаемо**:

- прогресс показывает общий процент, текущий том и путь;
- после завершения дерево содержит две строки верхнего уровня — оба тома;
- контекст дерева называет два тома;
- суммарный размер в дереве равен сумме размеров томов.

## 2. GUI: раскрытие, поиск и аналитика

1. Раскрыть второй том в дереве.
2. Открыть каталог и проверить хлебные крошки.
3. Найти по имени файл, который лежит только на втором томе.
4. Открыть «Крупнейшие файлы», «Типы», «Владельцы», «Дубликаты», «Очистку» и «Инспекцию».

**Ожидаемо**:

- доли элементов считаются от родителя и от всего снимка;
- поиск находит файл на втором томе;
- все экраны открываются без ошибок и содержат элементы обоих томов (где применимо).

## 3. GUI: частичный успех и отмена

1. Выбрать два тома, один из которых отключён или недоступен.
2. Запустить анализ.

**Ожидаемо**:

- доступный том появляется в дереве;
- предупреждение называет недоступный том и причину;
- задача имеет состояние «частично успешно».

3. Повторить с двумя доступными томами и нажать «Отмена» во время второго тома.

**Ожидаемо**:

- второй том не сканируется до конца;
- задача получает состояние «отменено»;
- интерфейс остаётся отзывчивым.

## 4. GUI: последовательное добавление томов

1. На снимке из одного тома выбрать второй том и запустить анализ.
2. Дождаться завершения.
3. Повторно проанализировать первый том.

**Ожидаемо**:

- после второго запуска снимок содержит оба тома;
- повторный анализ обновляет данные выбранного тома и не дублирует его корень;
- интерфейс явно показывает состав снимка; перезапуск приложения не требуется.

## 5. CLI: два пути

```powershell
freespace scan C:\ D:\ --json
freespace tree C:\ D:\ --depth 2 --json
```

**Ожидаемо**:

- `scan` возвращает `volumes` с двумя элементами, `roots` с двумя путями, суммарный `total`;
- `tree` возвращает два элемента в `roots`;
- JSON валиден; код возврата 0.

## 6. CLI: ошибки и границы

```powershell
freespace scan C:\ C:\ --json
freespace scan C:\ C:\Users --json
freespace scan C:\ D:\ E:\ F:\ ... (33 пути) --json
```

**Ожидаемо**:

- повтор, пересечение и превышение лимита отклоняются до сканирования;
- код возврата 2, понятное сообщение, скан не запускается.

```powershell
freespace scan C:\ --json
```

**Ожидаемо**:

- поведение и поля совместимы с одиночным томом; добавлены `volumes` и `methods`.

## 7. Производительность и память

- Один том 8 ТБ: ≤ 60 с на потребительском SSD (Windows, MFT).
- Два тома суммарно 8 ТБ: ≤ 120 с.
- 10 млн узлов по всем корням: ≤ 4 ГБ памяти.
- Корневая страница дерева: ≤ 200 мс.

Проверка: `cargo test --workspace`, затем ручной прогон на тестовых VHD; для памяти —
`cargo run --release -p freespace-cli -- scan <path> --json` под профилировщиком.

## 8. Регрессии

- Одиночный том: дерево, поиск, аналитика, операции, экспорт и файлы снимков работают как раньше.
- `volumes_current` возвращает первый том; `snapshot_volumes` — все.
- Журнал операции на втором томе содержит идентификатор второго тома.
- Отчёты и `.fssnap` записывают основной том и перечисляют все корни (ограничение фичи).
