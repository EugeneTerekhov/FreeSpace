## Clarifications

### Session 2026-11-15

- Q: Какой режим удаления должен использоваться по умолчанию для всех функций очистки? → A: Спрашивать каждый раз — при каждой разрушающей операции пользователь выбирает Корзину Windows, карантин приложения или безвозвратное удаление.
- Q: Что должна делать система, если для выбранного способа удаления (Корзина или карантин) недостаточно свободного места? → A: Предупредить и дать выбор — освободить место, выбрать безвозвратное удаление или отменить операцию.
- Q: Как должно вести себя приложение при безвозвратном удалении файлов на SSD? → A: Предупредить об ограничениях выравнивания износа, потребовать явного подтверждения, выполнить перезапись и инициировать TRIM.
- Q: Как определять «устаревшие» файлы, если Windows по умолчанию не ведёт дату последнего доступа? → A: Использовать максимум из даты доступа и даты изменения, помечая недостоверность даты доступа в интерфейсе и отчёте.
- Q: Входят ли сетевые расположения и облачные хранилища в область первой версии? → A: Нет, только локальные и подключённые тома; сетевые и облачные расположения вне области v1.

## User Scenarios & Testing *(обязательно)*

### User Story 1 — Быстрое сканирование тома и дерево размеров (Priority: P1)

Пользователь выбирает диск или каталог и запускает анализ. Через несколько секунд он видит иерархическое дерево, где для каждого узла показан размер, количество файлов и папок; дерево можно разворачивать, сортировать, фильтровать и искать по нему. Для NTFS-томов применяется прямое чтение главной файловой таблицы (MFT), для остальных файловых систем — обход дерева каталогов с явным указанием применённого метода. Повторный анализ тома поддерживает инкрементальное обновление по журналу изменений USN. Объекты, к которым нет доступа, помечаются и не искажают итоговые суммы.

**Why this priority**: это ядро продукта — все остальные функции работают на данных, собранных сканером. Без него приложение не имеет ценности.

**Independent Test**: просканировать тестовый том с заранее известной структурой и контрольными суммами размеров, убедиться, что дерево построено, суммы совпадают с эталоном, недоступные элементы помечены, поиск и сортировка работают.

**Acceptance Scenarios**:

1. **Given** пользователь выбрал NTFS-том, **When** он запускает анализ, **Then** результаты появляются постепенно, дерево доступно для навигации, а полный анализ тома до 8 ТБ завершается не дольше чем за 60 секунд на типичном потребительском SSD.
2. **Given** анализ завершён, **When** пользователь сортирует дочерние узлы по размеру, **Then** крупнейшие объекты находятся сверху, а суммы по узлам согласованы с размерами потомков.
3. **Given** в томе есть каталоги, недоступные текущему пользователю, **When** анализ завершён, **Then** эти каталоги отображаются с пометкой «нет доступа» и не искажают итоговые суммы.
4. **Given** выбран том с файловой системой, отличной от NTFS, **When** запускается анализ, **Then** применяется обход дерева, а метод сканирования явно показан в интерфейсе и отчёте.
5. **Given** анализ завершён, **When** пользователь вводит в поиск имя, маску или расширение, **Then** дерево фильтруется, показывая совпадения вместе с их родительскими узлами.
6. **Given** том уже сканировался и журнал изменений доступен, **When** пользователь запускает повторный анализ, **Then** обновляются только изменившиеся объекты, а результат помечается как инкрементальный.
7. **Given** анализ выполняется, **When** пользователь прокручивает дерево или меняет сортировку, **Then** интерфейс остаётся отзывчивым и показывает прогресс.

### User Story 2 — Интерактивная карта Treemap (Priority: P1)

Пользователь открывает визуальную карту, где каждый файл или папка представлен прямоугольником, площадь которого пропорциональна занимаемому месту. Карта поддерживает навигацию с погружением в каталоги, подсказки с полной информацией об объекте и раскраску по типам файлов, что позволяет мгновенно находить самые тяжёлые объекты.

**Why this priority**: визуальная карта — ключевой способ мгновенного обнаружения «пожирателей места» и главный дифференциатор продукта.

**Independent Test**: открыть карту для набора с известными размерами, проверить пропорциональность площадей, работу зума, подсказок и легенды цветов.

**Acceptance Scenarios**:

1. **Given** анализ завершён, **When** пользователь открывает карту, **Then** площадь каждого прямоугольника пропорциональна размеру объекта с точностью, достаточной для визуального сравнения.
2. **Given** карта отображается, **When** пользователь выбирает прямоугольник и погружается в него, **Then** карта перестраивается на выбранный каталог, а навигация назад доступна через «хлебные крошки».
3. **Given** карта отображается, **When** пользователь наводит курсор на прямоугольник, **Then** показываются имя, полный путь, размер и доля от родительского узла.
4. **Given** включена раскраска по типам файлов, **When** карта отрисована, **Then** файлы одного типа имеют одинаковый цвет, а легенда объясняет соответствие цветов.
5. **Given** том содержит миллионы файлов, **When** пользователь взаимодействует с картой, **Then** отрисовка остаётся отзывчивой за счёт уровней детализации.

### User Story 3 — Разблокировка занятых файлов (Priority: P1)

Пользователь узнаёт, какой процесс удерживает файл, и может снять блокировку, закрыв дескриптор или завершив процесс после подтверждения. Если блокировка находится на уровне ядра или драйвера, пользователь может поставить файл в системную очередь удаления при перезагрузке.

**Why this priority**: снятие блокировок — вторая базовая функция продукта, без которой невозможно удаление и перемещение занятых файлов.

**Independent Test**: создать файл, удерживаемый тестовым процессом, найти блокирующий процесс, снять блокировку и убедиться, что файл стал доступен; проверить постановку в очередь удаления при перезагрузке.

**Acceptance Scenarios**:

1. **Given** файл удерживается процессом, **When** пользователь выбирает «Кто блокирует?», **Then** отображается список процессов и дескрипторов с типом доступа.
2. **Given** список блокировок получен, **When** пользователь подтверждает снятие блокировки, **Then** дескриптор закрывается, а доступность файла проверяется повторной операцией.
3. **Given** файл заблокирован на уровне ядра или драйвера, **When** пользователь выбирает удаление при перезагрузке, **Then** операция регистрируется и выполняется до загрузки графической оболочки Windows.
4. **Given** операция разблокировки выполнена, **When** пользователь открывает журнал, **Then** он видит процесс, время, тип операции и результат.

### User Story 4 — Топ крупнейших файлов и группировка по типам (Priority: P1)

Пользователь открывает плоский список топ-100 или топ-1000 самых тяжёлых файлов без привязки к папкам, а также отдельный отчёт по расширениям и категориям, где видно, сколько места занимают видео, архивы, образы дисков, логи и другие типы данных.

**Why this priority**: это самые быстрые ответы на вопрос «что занимает место», которые пользователи ищут в первую очередь.

**Independent Test**: на наборе с известными файлами проверить корректность топ-списка при разных N, суммы и количество по расширениям, переход к объекту в дереве.

**Acceptance Scenarios**:

1. **Given** анализ завершён, **When** пользователь открывает «Топ файлов», **Then** отображается N крупнейших файлов с путями и размерами, а N настраивается (минимум 100 и 1000).
2. **Given** открыта вкладка «Типы», **When** пользователь выбирает расширение или категорию, **Then** видны суммарный размер, количество файлов и доля в занятом месте.
3. **Given** пользователь дважды щёлкает по записи списка, **When** открывается дерево, **Then** соответствующий узел выбран и подсвечен.
4. **Given** в топ-списке есть файл, к которому нет доступа, **When** список сформирован, **Then** файл присутствует с пометкой и не искажает суммы.

### User Story 5 — Поиск дубликатов и безопасное удаление копий (Priority: P2)

Пользователь ищет дубликаты по имени, размеру или контрольной сумме (MD5/SHA-256), получает группы полных совпадений с указанием потенциально освобождаемого места и применяет правила автовыбора копии, которую нужно оставить. Удаление копий выполняется только после предпросмотра и подтверждения, по умолчанию — в Корзину или карантин.

**Why this priority**: дубликаты — одна из самых частых причин потери свободного места; функция даёт немедленную практическую пользу.

**Independent Test**: подготовить набор с известными дубликатами (включая файлы одинакового размера с разным содержимым), проверить отсутствие ложных совпадений, работу правил выбора и сохранность одной копии.

**Acceptance Scenarios**:

1. **Given** пользователь выбрал области поиска, **When** запускается поиск по хешу, **Then** формируются группы полных побайтовых совпадений без ложных срабатываний.
2. **Given** группа дубликатов найдена, **When** пользователь применяет правило «оставить новейший/старейший/в исходном каталоге», **Then** к удалению помечаются остальные копии, но удаление не происходит до подтверждения.
3. **Given** пользователь подтверждает удаление, **When** операция завершается, **Then** копии перемещаются в выбранное безопасное место (Корзину или карантин) либо удаляются безвозвратно, если этот способ явно выбран, а как минимум одна копия гарантированно сохраняется.
4. **Given** файлы изменились во время поиска, **When** обнаружено расхождение, **Then** группа помечается как неактуальная и не предлагается к удалению.
5. **Given** пользователь отменил операцию, **When** он открывает журнал, **Then** может восстановить объекты из карантина.

### User Story 6 — Шредер и удаление при перезагрузке (Priority: P2)

Пользователь безвозвратно уничтожает выбранные данные путём перезаписи нулями или случайными числами с настраиваемым числом проходов. Приложение предупреждает о необратимости и об ограничениях гарантий на SSD. Для файлов, заблокированных на уровне ядра, доступна постановка в системную очередь удаления при перезагрузке.

**Why this priority**: функция востребована при передаче компьютера, утилизации дисков и удалении конфиденциальных данных.

**Independent Test**: уничтожить тестовый набор файлов и попытаться восстановить их независимым инструментом; проверить журнал, предупреждения и работу удаления при перезагрузке.

**Acceptance Scenarios**:

1. **Given** пользователь выбрал файлы для уничтожения, **When** он подтверждает операцию, **Then** выполняется перезапись выбранным методом и удаление, а восстановление файлов независимым инструментом невозможно.
2. **Given** выбран том на SSD, **When** открывается шредер, **Then** показывается предупреждение об ограничениях гарантий на SSD, требуется явное подтверждение, а после перезаписи инициируется TRIM.
3. **Given** операция завершена, **When** открыт журнал, **Then** зафиксированы объекты, метод, число проходов и результат.
4. **Given** файл заблокирован на уровне ядра, **When** выбрано удаление при перезагрузке, **Then** файл удаляется до загрузки графической оболочки, а результат виден после перезагрузки.

### User Story 7 — Устаревшие файлы, временные данные, пустые папки и рекомендации (Priority: P2)

Пользователь фильтрует данные по дате последнего открытия или изменения, находит забытые бэкапы, кэш программ, логи и временные файлы, а также пустые каталоги, оставшиеся после удаления программ. Отдельный экран рекомендаций предлагает безопасные категории очистки с оценкой освобождаемого объёма и уровня риска.

**Why this priority**: это готовые сценарии очистки, которые пользователь может применить сразу, не разбираясь в структуре диска.

**Independent Test**: на подготовленном наборе с известными датами и пустыми каталогами проверить точность фильтров, полноту списка пустых папок и корректность рекомендаций.

**Acceptance Scenarios**:

1. **Given** задан порог «не открывался более 180 дней», **When** применяется фильтр, **Then** список содержит только подходящие объекты, рассчитанные по максимуму из дат доступа и изменения, с указанием дат и пометкой недостоверности даты доступа.
2. **Given** анализ завершён, **When** открыт отчёт «Пустые папки», **Then** перечислены все пустые каталоги, включая вложенные, и доступно их пакетное удаление после подтверждения.
3. **Given** найдены кандидаты на очистку, **When** открыт экран рекомендаций, **Then** показаны категории с потенциальным объёмом и пояснением рисков.
4. **Given** пользователь выбирает рекомендацию, **When** он подтверждает действие, **Then** операция выполняется по общим правилам безопасности через Корзину или карантин.

### User Story 8 — Снимки состояния диска и сравнение (Priority: P2)

Пользователь сохраняет состояние диска в файл снимка, а через некоторое время сравнивает его с текущим состоянием и видит, какие папки разрослись, что появилось, что удалено и что изменилось.

**Why this priority**: сравнение во времени превращает разовый анализ в инструмент контроля роста данных и поиска утечек места.

**Independent Test**: создать два снимка с известными различиями, выполнить сравнение и проверить полноту и сортировку отчёта.

**Acceptance Scenarios**:

1. **Given** анализ завершён, **When** пользователь сохраняет снимок, **Then** создаётся версионированный файл с метаданными тома, даты и метода сканирования.
2. **Given** есть два совместимых снимка, **When** запускается сравнение, **Then** отчёт показывает прирост и уменьшение по каталогам и файлам.
3. **Given** сравнение выполнено, **When** пользователь сортирует по приросту, **Then** крупнейшие ухудшения находятся сверху.
4. **Given** сравниваются снимки разных томов или несовместимых версий формата, **When** запускается сравнение, **Then** выводится понятная ошибка без потери данных.

### User Story 9 — Безопасные операции: Корзина, карантин, журнал и отмена (Priority: P2)

Любая разрушающая операция проходит через единый механизм предпросмотра и подтверждения с указанием объектов, суммарного объёма и необратимости. Все операции записываются в журнал; удалённые объекты по умолчанию попадают в Корзину или карантин, откуда их можно восстановить; где возможно — доступна отмена.

**Why this priority**: это страховочный слой для всех функций очистки; без него приложение опасно использовать на реальных данных.

**Independent Test**: выполнить удаление, проверить наличие предпросмотра и подтверждения, восстановить объект из карантина, проверить запись в журнале и работу отмены.

**Acceptance Scenarios**:

1. **Given** пользователь инициирует разрушающую операцию, **When** открывается подтверждение, **Then** показаны список объектов, суммарный объём, предупреждение о необратимости и выбор способа удаления: Корзина Windows, карантин приложения или безвозвратное удаление.
2. **Given** операция выполнена, **When** пользователь открывает журнал, **Then** он видит параметры, результат и доступность отмены, если она применима.
3. **Given** объекты находятся в карантине, **When** пользователь выбирает «Восстановить», **Then** объекты возвращаются в исходные пути, а конфликты имён разрешаются предсказуемо.
4. **Given** операция затрагивает системный или защищённый путь, **When** пользователь её запрашивает, **Then** требуется повышение прав и дополнительное подтверждение.

### User Story 10 — Точный учёт места: ссылки, сжатие, разреженные файлы и ADS (Priority: P3)

Пользователь видит реальный расход места: жёсткие ссылки учитываются один раз на физический файл, junction-точки и символические ссылки не обходятся без явного указания, для сжатых и разреженных файлов показываются логический и физический размеры, а альтернативные потоки данных NTFS (ADS) перечислены и учтены.

**Why this priority**: без этого отчёты завышают занятое место и вводят в заблуждение при работе с образами виртуальных машин, сжатыми каталогами и системными файлами.

**Independent Test**: подготовить набор с жёсткими ссылками, junction, сжатыми и разреженными файлами и ADS, проверить соответствие логических и физических размеров эталону.

**Acceptance Scenarios**:

1. **Given** каталог содержит несколько жёстких ссылок на один файл, **When** анализ завершён, **Then** физический размер учтён один раз, логический — по числу ссылок, и оба значения показаны.

### Edge Cases

- Что происходит, когда файл или каталог изменяется либо удаляется во время сканирования? Сканирование MUST помечать такие объекты как «изменён во время анализа» и не искажать итоговые суммы.
- Как система обрабатывает том, отключённый или ставший недоступным во время операции? Операция MUST прерываться с понятной ошибкой, а уже выполненные действия MUST оставаться в журнале.
- Что происходит при циклических символических ссылках? Сканирование MUST обнаруживать циклы и не зацикливаться.
- Как обрабатываются пути длиннее системного предела? Операция MUST завершаться понятной ошибкой до изменения данных.
- Что происходит при прерывании разрушающей операции из-за сбоя питания? Журнал MUST позволять определить состояние и восстановить объекты из карантина.
- Что происходит, если для Корзины или карантина недостаточно свободного места? Система MUST показать требуемый объём и предложить освободить место, выбрать безвозвратное удаление или отменить операцию; частичное выполнение без явного подтверждения недопустимо.
- Как обрабатываются архивы с паролем, повреждённые архивы и архивы, распаковка которых требует несоразмерных ресурсов? Приложение MUST ограничивать ресурсы и сообщать о проблеме без аварийного завершения.
- Что происходит при совпадении имён при восстановлении из карантина или массовом переименовании? Конфликты MUST обнаруживаться до применения, а стратегия разрешения MUST быть предсказуемой.
- Как обрабатываются EFS-шифрованные, сжатые и разреженные файлы при шредер-удалении? Приложение MUST предупреждать об ограничениях гарантий.
- Что происходит, если портативный режим запущен из папки без прав на запись? Настройки MUST сохраняться в резервное расположение с уведомлением пользователя.
- Как обрабатывается одновременный запуск нескольких экземпляров приложения или конфликтующих задач по расписанию? Конфликтующие операции MUST блокироваться или ставиться в очередь.
- Как обрабатываются имена с Unicode, эмодзи и суррогатными парами? Отображение, поиск и операции MUST работать без потери данных.
- Что происходит при экспорте отчёта на миллионы строк? Экспорт MUST выполняться потоково и не приводить к исчерпанию памяти.
- Как обрабатываются файлы, у которых во время хеширования изменилось содержимое? Группа дубликатов MUST помечаться как неактуальная.

## Requirements *(обязательно)*

### Functional Requirements

**Сканирование, дерево и навигация**

- **FR-001**: Пользователь MUST иметь возможность выбрать для анализа том, каталог или набор каталогов.
- **FR-002**: Система MUST строить иерархическое дерево, в котором для каждого узла отображаются размер, количество файлов и количество вложенных каталогов.
- **FR-003**: Для NTFS-томов система MUST использовать прямое чтение MFT и MUST анализировать том объёмом до 8 ТБ не дольше чем за 60 секунд на типичном потребительском SSD.
- **FR-004**: Для файловых систем, отличных от NTFS, система MUST использовать обход дерева каталогов и MUST явно отображать применённый метод сканирования.
- **FR-005**: Система MUST отображать логический размер, размер на диске и, где применимо, физический размер объекта.
- **FR-006**: Система MUST помечать объекты, недоступные из-за прав, не прерывая анализ и не искажая итоговые суммы.
- **FR-007**: Система MUST поддерживать поиск и фильтрацию по имени, маске, расширению, размеру, датам, атрибутам, владельцу и метаданным.
- **FR-008**: Система MUST поддерживать сортировку по имени, размеру, дате, типу, владельцу и метаданным.
- **FR-009**: Система MUST поддерживать инкрементальное обновление повторного анализа NTFS-тома по журналу изменений USN.
- **FR-010**: Сканирование MUST выполняться в фоне с отображением прогресса и возможностью отмены, не блокируя интерфейс.
- **FR-011**: Пользователь MUST иметь возможность задать исключаемые пути, которые не учитываются при анализе.
- **FR-012**: При неизменной файловой системе результаты повторного сканирования MUST быть детерминированными.

**Treemap**

- **FR-013**: Система MUST отображать интерактивную карту Treemap, в которой площадь прямоугольника пропорциональна размеру объекта.
- **FR-014**: Карта MUST поддерживать погружение в каталоги, навигацию назад и «хлебные крошки».
- **FR-015**: Карта MUST показывать подсказку с именем, полным путём, размером и долей объекта.
- **FR-016**: Карта MUST поддерживать раскраску по типам файлов с легендой.
- **FR-017**: Карта MUST сохранять отзывчивость на томах с миллионами файлов за счёт уровней детализации и виртуализации отрисовки.

**Топ файлов и типы**

- **FR-018**: Система MUST формировать плоский список топ-N крупнейших файлов с настраиваемым N (не менее 100 и 1000).
- **FR-019**: Система MUST группировать занятое место по расширениям и категориям с указанием суммы, количества файлов и доли.
- **FR-020**: Система MUST обеспечивать переход из списка топ-файлов и групп по типам к соответствующему узлу дерева или карты.

**Разблокировка файлов**

- **FR-021**: Система MUST определять процессы и дескрипторы, удерживающие выбранный файл.
- **FR-022**: Система MUST позволять снимать блокировку закрытием дескриптора или завершением процесса только после явного подтверждения.
- **FR-023**: Система MUST позволять ставить заблокированный файл в системную очередь удаления при перезагрузке.
- **FR-024**: Все операции разблокировки MUST журналироваться с указанием процесса, времени и результата.

**Дубликаты**

- **FR-025**: Система MUST искать дубликаты по имени, размеру или контрольной сумме (MD5/SHA-256) в выбранной области.
- **FR-026**: Система MUST подтверждать совпадение полным побайтовым сравнением после сравнения хешей.
- **FR-027**: Система MUST группировать дубликаты и показывать потенциально освобождаемый объём.
- **FR-028**: Система MUST поддерживать правила автовыбора сохраняемой копии: старейшая, новейшая, кратчайший путь, исходный каталог.
- **FR-029**: Удаление дубликатов MUST выполняться только после предпросмотра и подтверждения и MUST гарантировать сохранение как минимум одной копии.

**Шредер и удаление при перезагрузке**

- **FR-030**: Система MUST выполнять безвозвратное удаление перезаписью нулями или случайными данными с настраиваемым числом проходов (не менее одного).
- **FR-031**: Для SSD система MUST показывать предупреждение об ограничениях гарантий, требовать явного подтверждения и после перезаписи инициировать TRIM; для HDD предупреждение ограничивается необратимостью операции.
- **FR-032**: Система MUST поддерживать постановку файлов в системную очередь удаления до загрузки графической оболочки Windows.
- **FR-033**: Операции шредера MUST журналироваться с указанием метода, числа проходов и результата.

**Устаревшие данные, пустые папки, рекомендации**

- **FR-034**: Система MUST фильтровать объекты по дате последнего доступа, изменения и создания с настраиваемыми порогами; для критерия «устаревший» MUST использоваться максимум из даты доступа и даты изменения, а недостоверность даты доступа MUST явно помечаться.
- **FR-035**: Система MUST выделять категории временных файлов, кэша, журналов и резервных копий по заданным правилам.
- **FR-036**: Система MUST находить пустые каталоги, включая вложенные, и поддерживать их пакетное удаление после подтверждения.
- **FR-037**: Система MUST формировать рекомендации по очистке с оценкой освобождаемого объёма и уровня риска.

**Снимки**

- **FR-038**: Система MUST сохранять снимок состояния диска в файл с метаданными тома, времени и метода сканирования и версией формата.
- **FR-039**: Система MUST сравнивать два снимка и показывать появившиеся, удалённые, изменённые объекты и прирост по каталогам.
- **FR-040**: Система MUST поддерживать сортировку результатов сравнения по приросту и экспорт отчёта сравнения.
- **FR-041**: Система MUST проверять совместимость снимков и выдавать понятную ошибку при несовпадении томов или версий формата.

**Безопасность операций**

- **FR-042**: Любая разрушающая операция MUST выполняться только после предпросмотра затронутых объектов, их суммарного объёма и явного подтверждения.
- **FR-043**: При каждой разрушающей операции система MUST предлагать пользователю выбор способа удаления: Корзина Windows, карантин приложения или безвозвратное удаление, с пояснением последствий каждого варианта; выбранный способ MUST применяться только к текущей операции. Если для выбранного способа недостаточно свободного места, система MUST показать требуемый объём и предложить освободить место, выбрать безвозвратное удаление или отменить операцию.
- **FR-044**: Система MUST вести журнал всех операций, поддерживать отмену там, где она возможна, и восстановление объектов из карантина.
- **FR-045**: Операции над системными и защищёнными путями MUST требовать повышенных прав и дополнительного подтверждения.
- **FR-046**: Система MUST гарантировать, что операции не выходят за пределы явно выбранной пользователем области.

**Ссылки, сжатие, разреженные файлы и ADS**

- **FR-047**: Система MUST различать жёсткие ссылки, junction-точки и символические ссылки, MUST помечать их и MUST NOT обходить ссылки без явного указания пользователя.
- **FR-048**: Система MUST учитывать жёсткие ссылки один раз в физическом размере и отдельно показывать их логический вклад.
- **FR-049**: Система MUST показывать логический и физический размер сжатых и разреженных файлов, а также объём экономии.
- **FR-050**: Система MUST перечислять альтернативные потоки данных NTFS и учитывать их размер.

**Длинные пути**

- **FR-051**: Система MUST выполнять переименование, перемещение, копирование и удаление для путей длиннее 260 символов без включения системной политики длинных путей.
- **FR-052**: При превышении системного предела длины пути система MUST выдавать понятную ошибку до изменения данных.
- **FR-053**: Журналы и отчёты MUST содержать полные пути без усечения.

**Массовое переименование**

- **FR-054**: Система MUST поддерживать правила переименования на основе регулярных выражений, шаблонов, изменения регистра, расширений, нумерации и метаданных.
- **FR-055**: Система MUST показывать предпросмотр, обнаруживать конфликты и поддерживать откат выполненного переименования.
- **FR-056**: Массовое переименование тысяч файлов MUST выполняться без блокировки интерфейса с отображением прогресса.

**Атрибуты и права NTFS**

- **FR-057**: Система MUST поддерживать пакетную установку и снятие атрибутов «Только чтение», «Скрытый», «Системный» и «Архивный».
- **FR-058**: Система MUST поддерживать пакетную смену владельца, сброс и копирование прав NTFS, а также управление наследованием.
- **FR-059**: Операции с правами MUST сопровождаться отчётом об успешных и неуспешных объектах с указанием причин.
- **FR-060**: При недостатке прав система MUST запрашивать повышение прав и MUST понятно объяснять отказ.

**Метаданные**

- **FR-061**: Система MUST читать и отображать метаданные: EXIF (модель камеры, дата съёмки, разрешение), аудио (битрейт, длительность), видео (разрешение, кодек, длительность), исполняемые файлы (версия файла и продукта).
- **FR-062**: Система MUST поддерживать фильтрацию и сортировку по поддерживаемым метаданным.
- **FR-063**: Ошибки чтения метаданных MUST не прерывать работу приложения и MUST отображаться как «н/д».

**Владельцы**

- **FR-064**: Система MUST формировать отчёт о суммарном объёме и количестве файлов по владельцам с категорией «неизвестно».
- **FR-065**: Система MUST поддерживать фильтрацию дерева и списков по владельцу.

**Архивы**

- **FR-066**: Система MUST отображать содержимое архивов ZIP, 7z, TAR/GZ, ISO и RAR (при наличии совместимой библиотеки) без полной распаковки.
- **FR-067**: Система MUST показывать размеры элементов архива и их долю в содержимом, а также поддерживать поиск крупнейших элементов.
- **FR-068**: Система MUST корректно обрабатывать архивы с паролем, повреждённые архивы и ограничивать ресурсы при подозрении на архивные бомбы.
- **FR-069**: Система MUST поддерживать экспорт списка содержимого архива.

**Экспорт отчётов**

- **FR-070**: Система MUST экспортировать результаты анализа в CSV, XML, HTML и Excel.
- **FR-071**: Пользователь MUST иметь возможность выбрать состав и область экспортируемого отчёта.
- **FR-072**: Экспорт MUST корректно работать с кодировками, большими объёмами данных и MUST сохранять согласованность сумм.
- **FR-073**: Форматы и схемы отчётов MUST быть документированы.

**Командная строка и расписание**

- **FR-074**: Каждая функция графического интерфейса MUST иметь аналог в командной строке с машиночитаемым выводом (JSON) и сообщениями об ошибках в потоке ошибок.
- **FR-075**: Командная строка MUST поддерживать неинтерактивный режим и MUST требовать явного флага подтверждения для разрушающих операций.
- **FR-076**: Коды возврата команд MUST быть документированы и стабильны в пределах мажорной версии.
- **FR-077**: Система MUST предоставлять примеры и шаблоны для запуска через Планировщик заданий Windows.
- **FR-078**: Система MUST предотвращать конфликтующие параллельные запуски или ставить их в очередь.

**Контекстное меню**

- **FR-079**: Система MUST добавлять в контекстное меню Проводника пункты анализа размера и разблокировки для файлов, папок и томов.
- **FR-080**: Система MUST поддерживать установку и удаление интеграции как для текущего пользователя, так и для всех пользователей при наличии прав.
- **FR-081**: Передача путей из контекстного меню MUST корректно работать с пробелами, Unicode и длинными путями.

**Мониторинг в реальном времени**

- **FR-082**: Система MUST отображать процессы, пути и скорость записи на диск в реальном времени.
- **FR-083**: Система MUST поддерживать уведомления при превышении заданных порогов и хранить историю событий.
- **FR-084**: Мониторинг MUST работать в фоновом режиме и в области уведомлений с минимальным влиянием на систему.
- **FR-085**: Пользователь MUST иметь возможность исключать процессы и пути из мониторинга.

**Права и системные каталоги**

- **FR-086**: Система MUST запрашивать повышение прав по требованию с пояснением причины.
- **FR-087**: При наличии прав система MUST обеспечивать доступ к System Volume Information и другим защищённым каталогам.
- **FR-088**: Без повышенных прав система MUST корректно деградировать, помечая недоступные области.

**Дашборд дисков**

- **FR-089**: Система MUST показывать сводку по всем доступным томам: общий объём, занятое и свободное место, тип файловой системы.
- **FR-090**: Система MUST обеспечивать быстрый запуск анализа выбранного тома и отображение динамики занятости по сохранённым снимкам.

**Настройки, локализация и портативность**

- **FR-091**: Пользователь MUST настраивать единицы измерения, исключения, пороги, тему оформления и язык интерфейса.
- **FR-092**: Интерфейс MUST быть полностью локализован на русский и английский языки; переключение языка MUST NOT приводить к потере текущего состояния.
- **FR-093**: Система MUST поддерживать портативный режим с хранением настроек и журналов рядом с исполняемым файлом и MUST корректно работать при отсутствии прав на запись в эту папку.
- **FR-094**: Приложение MUST NOT отправлять телеметрию и MUST NOT выполнять сетевые запросы по умолчанию.
- **FR-095**: Все функции приложения MUST быть доступны без подключения к сети.

### Key Entities *(включая данные, если применимо)*

- **Том (Volume)**: диск или раздел; атрибуты — буква, метка, файловая система, общий/занятый/свободный объём, метод сканирования, доступность.
- **Узел файловой системы (FsNode)**: файл, каталог или ссылка; атрибуты — имя, полный путь, тип, размеры (логический, на диске, физический), даты, атрибуты, владелец, признак доступности.
- **Метрики размера (SizeMetrics)**: логический размер, размер на диске, выделенный размер, вклад жёстких ссылок, размер альтернативных потоков.
- **Ссылка (FsLink)**: тип (жёсткая, junction, символическая), цель, признак учёта целевого объекта.
- **Сессия сканирования (ScanSession)**: том, область, метод, время начала и завершения, статус, исключения, ошибки доступа.
- **Группа дубликатов (DuplicateGroup)**: контрольная сумма, размер, список участников, рекомендуемая к сохранению копия, признак актуальности.
- **Кандидат на очистку (CleanupCandidate)**: категория, причина, объём, уровень риска, рекомендуемое действие.
- **Снимок (Snapshot)**: версия формата, том, дата, метод сканирования, агрегированные данные дерева.
- **Дельта снимков (SnapshotDiff)**: добавленные, удалённые, изменённые объекты и прирост по каталогам.
- **Блокировка файла (FileLock)**: процесс, идентификатор процесса, дескриптор, тип доступа, возможность снятия.
- **Операция (Operation)**: тип, список объектов, параметры, статус, обратимость, требование прав.
- **Запись журнала (JournalEntry)**: время, пользователь, операция, результат, возможность отката.
- **Элемент карантина (QuarantineItem)**: исходный путь, дата помещения, причина, срок хранения, статус восстановления.
- **Отчёт (Report)**: формат, состав, область, путь к файлу, дата создания.
- **Профиль автоматизации (AutomationProfile)**: команда, параметры, расписание, код возврата, путь к журналу.
- **Событие мониторинга (DiskEvent)**: процесс, путь, скорость записи, объём, время.
- **Метаданные (MetadataRecord)**: тип файла, теги и значения (EXIF, аудио, видео, версия исполняемого файла).
- **Сводка по владельцу (OwnerSummary)**: владелец, суммарный объём, количество файлов.
- **Элемент архива (ArchiveEntry)**: путь внутри архива, размер, сжатый размер, доля.
- **Настройки (Settings)**: единицы измерения, исключения, пороги, тема, язык, режим хранения (обычный/портативный).

## Success Criteria *(обязательно)*

### Measurable Outcomes

- **SC-001**: Полный анализ NTFS-тома объёмом 8 ТБ на типичном потребительском SSD занимает не более 60 секунд.
- **SC-002**: Интерфейс остаётся отзывчивым во время сканирования и длительных операций: реакция на действия пользователя не превышает 200 мс, прогресс отображается постоянно.
- **SC-003**: На контрольном наборе данных расхождения между размерами в приложении и эталонными значениями составляют 0 байт, включая жёсткие ссылки, сжатые, разреженные файлы и ADS.
- **SC-004**: Поиск дубликатов на контрольном наборе находит 100% истинных дубликатов и не выдаёт ни одного ложного совпадения.
- **SC-005**: Ни один объект не удаляется без явного подтверждения; 100% разрушающих операций фиксируются в журнале.
- **SC-006**: После работы шредера на контрольном наборе независимый инструмент восстановления не восстанавливает ни одного файла (для HDD).
- **SC-007**: 100% операций с путями длиной от 261 до 32 000 символов завершаются успешно или с понятной ошибкой до изменения данных.
- **SC-008**: Сравнение снимков в контрольном сценарии выявляет 100% добавленных, удалённых и изменённых объектов.
- **SC-009**: Все четыре формата экспорта открываются целевыми инструментами без ошибок, а суммы в отчётах совпадают с приложением.
- **SC-010**: 100% возможностей графического интерфейса доступны из командной строки; машиночитаемый вывод проходит валидацию по документированной схеме.
- **SC-011**: На подготовленном контрольном наборе типовой сценарий очистки позволяет освободить не менее 10 ГБ за время не более 10 минут, включая подтверждение операций.
- **SC-012**: 100% строк интерфейса имеют переводы на русский и английский языки; переключение языка не приводит к потере данных состояния.
- **SC-013**: В портативном режиме 100% настроек и журналов размещаются в папке приложения и ни одна запись не создаётся в профиле пользователя.
- **SC-014**: Событие записи на диск отображается в мониторинге не позднее чем через 2 секунды после начала записи, а накладные расходы в простое не превышают 2% процессора.
- **SC-015**: Не менее 80% участников тестирования находят крупнейший файл тома без инструкции быстрее чем за 1 минуту после запуска анализа.
- **SC-016**: Запуск анализа выбранного объекта из контекстного меню открывает приложение с нужным путём не дольше чем за 2 секунды.

## Assumptions

- Целевые операционные системы — Windows 10 версии 21H2 и новее, а также Windows 11, архитектура x64; основной сценарий — локальные диски с NTFS.
- Сетевые расположения (включая UNC-пути), облачные хранилища и удалённые машины не входят в область v1; анализируются только локальные и подключённые тома, включая съёмные носители с поддерживаемыми файловыми системами. Для не-NTFS томов применяется обход дерева в режиме ограниченной функциональности.
- Пользователь имеет возможность повысить права до администратора для доступа к системным каталогам, смены владельца и прав NTFS; без повышения приложение работает в ограниченном режиме.
- Приложение предназначено для локального использования одним пользователем; серверный и многопользовательский режимы не входят в область v1.
- Для просмотра RAR может использоваться сторонняя библиотека; при её отсутствии архив отображается как обычный файл с пояснением.
- Гарантии безвозвратного удаления на SSD ограничены внутренней логикой выравнивания износа; приложение обязано предупреждать об этом.
- Снимки хранятся в локальных файлах и совместимы в пределах мажорной версии формата; перенос снимков между машинами допускается при совпадении тома.
- Отчёты в формате Excel создаются в формате, открываемом Microsoft Excel и LibreOffice Calc без дополнительных настроек.
- Языки интерфейса v1 — русский и английский; при отсутствии перевода строки отображается на английском.
- Приложение не выполняет восстановление удалённых файлов, дефрагментацию, резервное копирование, антивирусную проверку и не управляет другими компьютерами.
- Кроссплатформенность (Linux, macOS) не входит в область v1.
- Одновременно на одном томе может выполняться только одна разрушающая операция; остальные ставятся в очередь или блокируются с понятным сообщением.
