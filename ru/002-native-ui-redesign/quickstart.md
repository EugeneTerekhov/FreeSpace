# Quickstart: проверка интерфейса 002

**Feature**: `002-native-ui-redesign` | **Date**: 2026-11-16

Руководство описывает, как собрать и проверить новый интерфейс после появления скелета
`apps/freespace-desktop`. Все разрушающие сценарии выполняются только на временных каталогах
и тестовых VHD; реальные пользовательские данные не затрагиваются.

## 1. Предварительные требования

- Windows 10 21H2+ или Windows 11, x64.
- Rust stable 1.85+ (edition 2024) и компонент `rustfmt`/`clippy`.
- Node.js 20.19+ и npm.
- WebView2: системный или fixed runtime из поставки.
- Для E2E: `tauri-driver` и Edge WebDriver, совместимый с установленным WebView2.
- Для административных сценариев: отдельный тестовый NTFS-том/VHD и
  `FREESPACE_ADMIN_TESTS=1`.
- Свободное место для `target/`, `node_modules/` и тестовых образов.

Проверка окружения:

```powershell
rustc --version
cargo --version
node --version
npm --version
```

## 2. Установка зависимостей

```powershell
# Rust workspace
cargo fetch

# Frontend
cd apps/freespace-desktop/ui
npm ci

# Браузеры Playwright (один раз на машину)
npx playwright install chromium
```

## 3. Запуск в режиме разработки

```powershell
cd apps/freespace-desktop/ui
npm run tauri dev
```

Ожидаемо:

- открывается нативное окно Windows с системным заголовком;
- тема применяется до первой отрисовки, без вспышки;
- оболочка показывает 24 экрана в боковой навигации;
- экран «Диски» загружает список томов;
- в `data/webview2` создаётся профиль WebView2, а не в `%LOCALAPPDATA%`;
- в `data/settings.toml` появляется секция `[ui]`;
- сетевые запросы отсутствуют.

## 4. Сборка

```powershell
cd apps/freespace-desktop/ui
npm run build

cd ..
cargo build --release -p freespace-desktop
```

Артефакты:

- `target/release/freespace-gui.exe` (имя сохраняется);
- frontend-ассеты внутри Tauri-бандла;
- установщик и portable ZIP — командой `npm run tauri build` (см. сценарий 11).

## 5. Обязательные проверки

```powershell
# Rust
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace

# Frontend
cd apps/freespace-desktop/ui
npm run typecheck
npm run lint
npm run test:unit
npm run test:e2e
npm run test:a11y
npm run test:visual
npm run check:i18n
npm run check:tokens
npm run check:network
```

Ожидаемо: все команды зелёные; `check:i18n` не находит diff сгенерированных каталогов;
`check:tokens` не находит жёстких цветов; `check:network` не находит сетевых вызовов.

## 6. Сценарий 1 — Ядро: диски, сканирование, дерево, карта (US1)

1. Подготовьте тестовый каталог с известной структурой или тестовый VHD:

   ```powershell
   $root = Join-Path $env:TEMP "freespace-ui-fixture"
   New-Item -ItemType Directory -Force $root | Out-Null
   1..2000 | ForEach-Object {
       $dir = Join-Path $root ("dir{0:D3}" -f ($_ % 40))
       New-Item -ItemType Directory -Force $dir | Out-Null
       Set-Content -Path (Join-Path $dir ("file{0:D4}.bin" -f $_)) -Value ("x" * ($_ % 4096))
   }
   ```

2. Откройте «Диски», выберите тестовый том/каталог, запустите анализ.
3. Убедитесь, что прогресс, текущий путь, число объектов и время обновляются; UI не
   замирает.
4. Нажмите «Отменить» во время анализа: задача останавливается ≤ 2 с, результаты помечены
   как неполные.
5. Запустите анализ снова до завершения.
6. Откройте «Дерево»: строки появляются ≤ 1 с, раскрытие/сворачивание работает, суммы
   совпадают с эталоном.
7. Откройте «Карту»: площади пропорциональны, погружение и «хлебные крошки» работают,
   выделение синхронизировано с деревом и панелью деталей.
8. На контрольном наборе 10 млн узлов проверьте 200 мс/30 fps/4 ГБ (см. раздел 16).

Ожидаемо: ни одна операция не блокирует оболочку; при 10 млн узлов UI остаётся отзывчивым.

## 7. Сценарий 2 — Анализ и очистка (US2)

1. На тестовом наборе откройте «Крупнейшие файлы», выберите N=100 и N=1000, примените
   фильтр по типу и пути.
2. Откройте «Типы», выберите расширение/категорию, сверьте сумму, количество и долю.
3. Откройте «Дубликаты», запустите поиск, примените правило «оставить одну копию», но не
   подтверждайте удаление.
4. Откройте «Очистка», выберите рекомендацию, проверьте объём, риск и переход в
   предпросмотр.
5. Создайте два снимка с известными различиями и выполните сравнение; проверьте сортировку
   по приросту.
6. Попробуйте сравнить несовместимые снимки: должна быть понятная ошибка без изменения
   файлов.

Ожидаемо: суммы совпадают с эталоном; ни одна копия не удаляется без подтверждения.

## 8. Сценарий 3 — Безопасные операции (US3)

Только временный каталог:

```powershell
$ops = Join-Path $env:TEMP "freespace-ui-ops"
New-Item -ItemType Directory -Force $ops | Out-Null
1..20 | ForEach-Object { Set-Content (Join-Path $ops "victim$_.txt") "test" }
```

1. Выберите файлы, инициируйте удаление.
2. Проверьте предпросмотр: список, суммарный объём, способ удаления, предупреждения.
3. Выполните удаление в Корзину; проверьте запись в журнале и восстановление.
4. Повторите с карантином; восстановите объекты.
5. Повторите с безвозвратным удалением; убедитесь, что требуется дополнительное
   подтверждение.
6. Отмените операцию до её завершения; проверьте фактический результат в журнале.
7. Попробуйте операцию на системном пути без elevation: должен быть запрос прав и отказ без
   изменения данных.

Ожидаемо: 100% операций проходят предпросмотр, подтверждение и журнал; отмена доступна там,
где операция обратима.

## 9. Сценарий 4 — ФС и операции (US4)

1. Создайте путь > 260 символов (временный каталог, без системной политики).
2. Откройте «Длинные пути», проверьте отображение, копирование полного пути, переименование
   и удаление.
3. Откройте «Детали размера»: проверьте логический/на диске/физический размер, ADS, сжатие,
   sparse и подпись типа метрики.
4. Откройте «Переименование»: задайте шаблон, проверьте предпросмотр старых/новых имён,
   конфликты и количество объектов.
5. Откройте «Права»: проверьте ACL/атрибуты, предпросмотр и отказ без elevation.
6. Проверьте журнал: полный путь, код ошибки и результат.

Ожидаемо: длинные пути работают без `LongPathsEnabled`; ни одна операция не выполняется без
предпросмотра.

## 10. Сценарий 5 — Инспекция и отчёты (US5)

1. Откройте «Метаданные» на EXIF/аудио/видео/PE-файле; проверьте источник и пустые значения.
2. Откройте «Владельцы»: проверьте суммы, количество и переход к файлам.
3. Откройте «Архивы»: проверьте список содержимого, размеры и долю; парольный/повреждённый
   архив не должен распаковываться на диск.
4. Выполните экспорт CSV, XML, HTML, XLSX; сверьте суммы с UI.
5. Откройте удерживаемый файл в «Разблокировке»: проверьте процессы и снятие блокировки после
   подтверждения.
6. Проверьте постановку в очередь удаления при перезагрузке (если доступно).

Ожидаемо: чтение не изменяет файлы; экспорт открывается целевыми инструментами.

## 11. Сценарий 6 — Операции и настройки (US6)

1. В «Настройках» переключите тему, язык, плотность, единицы и reduced motion; проверьте
   отсутствие перезапуска и потери состояния.
2. В «Шредере» выберите временный файл, проверьте метод, проходы и предупреждения; запустите
   только на временном файле.
3. Включите «Мониторинг записи», создайте запись на диск, проверьте событие ≤ 2 с и фильтры.
4. Проверьте «Elevation»: причина, согласие/отказ, отсутствие изменений при отказе.
5. Откройте «О программе»: версия, сборка, WebView2, лицензии, `data_dir` без сетевых
   запросов.

Ожидаемо: настройки применяются мгновенно; шредер не запускается без отдельного
подтверждения.

## 12. Сценарий 7 — Темы, DPI и motion (US7)

1. Переключите тёмную/светлую/системную тему на каждом экране.
2. Перезапустите приложение: вспышки неправильной темы нет.
3. Смените тему Windows при выбранной системной: UI обновляется без перезапуска.
4. Проверьте 100/125/150/200% DPI: нет обрезания, наложения, недоступных кнопок.
5. Включите «Уменьшение движения» в Windows: необязательные переходы отключаются.

Ожидаемо: контраст AA, палитры Treemap для обеих тем, состояние не теряется.

## 13. Сценарий 8 — Доступность (US8)

1. Отключите мышь/трекпад.
2. Пройдите сценарии: навигация, поиск, выбор, открытие диалога, подтверждение, отмена,
   переключение темы и языка.
3. Проверьте порядок фокуса и возврат фокуса после диалога.
4. Включите Narrator: проверьте заголовки, прогресс, ошибки, `aria-live`.
5. Проверьте, что статус не передаётся только цветом.

Ожидаемо: десять ключевых сценариев выполняются только с клавиатуры; Narrator не находит
блокирующих дефектов.

## 14. Сценарий 9 — Локализация (US9)

1. Переключите RU/EN на каждом экране.
2. Убедитесь, что фильтры, выделение, прогресс и позиция прокрутки сохраняются.
3. Проверьте отсутствие непереведённых строк и кириллицы в `en`.
4. Проверьте числа, даты и единицы (binary/decimal).
5. Запустите `npm run check:i18n`: diff сгенерированных каталогов отсутствует.

Ожидаемо: 100% строк локализованы; missing-key нет.

## 15. Сценарий 10 — Визуальная регрессия (US10)

```powershell
cd apps/freespace-desktop/ui
npm run test:visual
npm run test:visual:update   # только после осознанного ревью diff
```

Полная матрица: 24 экрана × 2 темы × 4 DPI × 2 языка. PR-набор — критические 8 экранов и все
24 в тёмной теме, 100%, RU. Ожидаемо: эталоны совпадают; намеренное изменение токена ломает
тест.

## 16. Производительность на 10 млн узлов

1. Сгенерируйте синтетический набор (только временный каталог/VHD):

   ```powershell
   cargo run -p freespace-app --example gen_fixture -- --nodes 10000000 --out $env:TEMP\freespace-10m
   ```

2. Запустите анализ и проверьте:
   - первый интерактивный экран ≤ 3 с;
   - первый экран с данными ≤ 5 с после готовности;
   - отклик ≤ 200 мс;
   - Treemap ≥ 30 fps;
   - память всего дерева процессов ≤ 4 ГБ.
3. Зафиксируйте результаты в отчёте производительности (FR-130).

## 17. Сценарий 11 — Поставка, офлайн и замена интерфейса (US11)

1. Соберите установщик и portable ZIP на чистой Windows-машине без сети.
2. Установите: WebView2 ставится офлайн, приложение запускается, сетевых запросов нет.
3. Проверьте `data` рядом с exe, `data/webview2`, отсутствие записей в `%APPDATA%`,
   `%LOCALAPPDATA%`, `%ProgramData%`.
4. Проверьте имя `freespace-gui.exe`, ярлыки и контекстное меню (по умолчанию выключено).
5. Удалите приложение: файлы, `data` и записи меню удалены; пользовательские файлы вне
   приложения не затронуты.
6. Убедитесь, что в поставке и workspace нет egui-приложения; собран ровно один GUI.

Ожидаемо: установка/запуск/удаление без сети; один UI; CLI-контракт не изменён.

## 18. Критерии приёмки

- [ ] 24/24 экрана реализованы и проходят сценарии.
- [ ] 0 сетевых вызовов; CSP и capabilities минимальны.
- [ ] 200 мс / 30 fps / 4 ГБ на контрольном наборе.
- [ ] AA в обеих темах; DPI 100–200%; reduced motion.
- [ ] RU/EN без missing-key; 0 жёстких строк и цветов.
- [ ] 100% разрушающих операций с предпросмотром, подтверждением и журналом.
- [ ] Rust-, unit-, E2E-, visual- и a11y-тесты зелёные.
- [ ] Установка/удаление без сети; `data` только рядом с exe.
- [ ] egui удалён; один GUI; CLI-контракт не изменён.
- [ ] Матрица паритета заполнена и проверена.

## 19. Диагностика

| Симптом | Проверка |
|---------|----------|
| Окно не открывается | WebView2 установлен/совместим; `data/webview2` доступен на запись |
| Тема мигает | `boot.js` загружается до CSS; `window.__FREESPACE_BOOT__` заполнен |
| Настройки не сохраняются | `data/settings.toml` доступен; нет ошибки прав; миграция версии |
| Данные не появляются | `app_capabilities`, `scan_status`, `generation`, `stale_cursor` |
| Treemap тормозит | `max_tiles`, `min_tile_px`, размеры viewport, Canvas DPR |
| E2E не стартует | `tauri-driver`, Edge WebDriver, версия WebView2 |
| Визуальный тест нестабилен | шрифты, DPI, viewport, допуск, Windows CI |
| Сеть detected | CSP, WebView2 args, network guard, отсутствие remote URL |
